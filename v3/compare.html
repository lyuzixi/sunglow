六、已知限制（分版本）

原版

  • 额度纪律：地图必须显式点击才取（~171 调用）；唯一例外是缓存命中自动画（零请求）。
  • 可信范围：色面边界＝采样点凸包 + 70km 羽化；凸包之外即外推，叠可信度纱（覆盖已上色面积约 21.6%）。
  • 模型分歧：少于两套有值时返回「无数据」而非 0（避免把缺模型伪装成高一致）。
  • XSS：49 处 innerHTML 插值，已加 esc()/safeLabel()，但仍有 44 处待替换，且缺 CSP。
  • 地图合规：需 TMap key + 代理；file:// 打开无图。换 OSM 等境外底图会引入合规风险。
  • PWA 默认关闭：与「单文件产物」约束冲突，需手动 PWA=1。

V2

  • 仍依赖 TMap（需网络/代理/key），离线地图不可用。
  • 首发 README 标注「首发不带测试、地图代理与部署暂缓」—— 后续已补探针，但部署形态未定型。
  • 与原版同样的 Open-Meteo 额度约束。

V3

  • 二期未做：明细区（天色带/因素/逐时/模式对比）、应用内教程、分享卡、校准档案、窄屏横滑与地图浮卡键盘可达。
  • 无跨城对比：不能直接回答「今天去哪拍」跨城，只能单城周边 Top3。
  • 时区弱化：todayStr() 取浏览器当地；当浏览器时区 ≠ 查询城市时区且接近当地午夜时，选中日期可能比城市当地差一天，事件时刻仍按城市算→轻微错位。
  • 无 URL 深链：分享特定地点/日期需靠快照功能（UI 未做），当前链接不带地点/日期。
  • 地图为自绘 Canvas：无真实底图/省界/卫星，交互精度不如 TMap；但换来了完全离线、零外部依赖与零合规风险。
  • 无 PWA：依赖单文件离线，未做 SW 缓存。

七、关键差异详解（具体表现 · 触发条件 · 用户影响）

差异点（版本）具体表现触发条件对用户的影响
地图引擎
V3·移除 TMap		 V3 改用 Canvas 自绘航图（色面+经纬网+罗盘+比例尺+Top3 pin+太阳方位线）；原版/V2 用腾讯地图 JS API（需服务端代理与 key）。 任何打开 V3 地图主舞台；或原版/V2 在 file:// / 无代理环境打开地图。 V3 双击/断网即出图、零部署成本、无合规风险；但失去真实底图、省界与卫星图层，交互（缩放/平移/地标搜索）不如 TMap 丰富。
确定性 MOCK 回落
V2·新增		 V2/V3 在网络失败或超时时回落到确定性（非随机）演示数据并标注 MOCK；原版无此分支，数据失败即降级/报错。 断网、Open-Meteo 不可达、或超过超时预算（V2 为 9s）。 V2/V3 离线也能看到完整界面与演示结论，便于演示/弱网；原版离线只能看壳或报错，且 MOCK 数据不可当真。
跨城对比（F2）
V3·移除		 V3 无「收藏多点横向排序」，仅有单城周边 57 点的 Top3 推荐；原版收藏 5 点、V2 compare.ts CMP_MAX=4。 用户想比较多座城市「今天去哪拍」。 V3 必须逐城切换、逐次查看，无法直接横向排名；跨城决策效率低于原版/V2。
明细区（天色带/因素/逐时）
V3·暂缺		 V3 的 skyCloud/factorRows 已在 forecast.ts 算好，但无 UI 组件；原版/V2 有完整天色带、13 项因素分解、逐时表。 用户想看「为什么是好/差」的逐项分解与逐时走势。 V3 一期只给结论+推荐+可信度，缺少「成因明细」，说服力与可解释性弱于原版/V2；二期补。
严格城市当地钟
V3·变更 弱化		 V2 用 tz.ts 按城市 IANA + utc_offset_seconds 算「城市当地今天」；V3 的 todayStr() 用 new Date()（浏览器当地），仅 API 层做偏移对齐。 浏览器时区 ≠ 查询城市时区，且接近该城市当地午夜时。 跨时区用户可能选中日期比城市当地差一天；事件时刻仍按城市算，出现「日期与事件轻微错位」。V2 无此问题。
URL 深链（地点/日期）
V3·移除		 原版/V2 把地点与日期写进 URL（?name=/urlstate），链接可复现；V3 仅 hash 路由，偏好只在 localStorage。 用户想分享「某地某日」的精确链接。 V3 当前链接不带地点/日期，分享需等快照 UI（二期）；原版/V2 链接可直达。
应用内教程
V3·移除		 V3 无自带教程，跳转原版 tutorial.html；原版独立教程、V2 应用内 Tutorial 视图。 新用户点击「教程 / 指南」。 V3 用户被带到视觉/交互不同的原版教程页，体验割裂；且原版教程不覆盖 V3 指挥台 IA。
校准 / 分享卡
V3·暂缺		 V3 的 calib.ts/snap.ts 已移植（口径与原版一致），但 UI 未做（可信度翼仅占位「敬请期待」）。 用户想做本地校准或导出分享卡。 二期前完全不可用；原版/V2 已可校准与分享。
算法口径回正
V3·变更		 V3 修正了 V2 的 3 处漂移：mixedIndex 权重回正 0.55/0.45、综合回正 wgeo、一致性公式回正；以原版为唯一权威。 任何结论/分歧/一致性计算。 V3 的综合指数、模型分歧、一致性最贴近原版权威口径；V2 在漂移期结论可能有细微偏差。
部署产物形态
V3·新增 双轨		 V3 同时产出 dist/（多文件，部署用）与 standalone.html（单文件，断网双击）；原版单文件+PWA 可选；V2 单文件。 部署到静态托管 vs 本地双击分发。 V3 兼顾「易部署」与「易离线分发」；原版需 PWA=1 才离线，V2 仅单文件。

八、结论与选型建议

  • 功能完整度：原版 ≥ V2 ＞ V3（V3 一期是聚焦 MVP，把明细区/对比/校准/分享/教程推迟到二期）。
  • 离线 & 零部署：V3 最佳（Canvas 航图 + standalone 双击即开，无需代理/key）；原版需 PWA=1，V2 单文件但地图仍需 TMap。
  • 算法可信度：V3 已回正 V2 漂移，结论口径最贴近原版权威；三版核心预报算法同源。
  • 决策体验：V3 的「指挥台 + 双主轴（去哪拍 / 敢不敢信）」是针对「今晚去哪拍」场景的重新设计，比原版/V2 的长页更聚焦；但代价是丢了跨城对比与明细解释。
  • 合规：原版/V2 用 TMap（具测绘资质）；V3 用 Canvas 自绘无行政边界，无合规风险但也无底图。
