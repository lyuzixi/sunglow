05五条硬依赖陷阱：文件能删，目录不能删

这一节是整份方案里唯一「删错了会立刻炸」的部分。前两条是「目录与夹具被当成了临时工位」，后三条是容易被误判的边界。执行前先跑 §7 的第 0 步自检。

  1. _scratch/_check/ 这个目录必须留下（内容可以清空） syntax.py 第 11 行 io.open(os.path.join(BASE,"_scratch","_check","chk%d.js"))、 run_self.py 第 18 行写 selfrun.js —— 两处都直接 io.open 写，没有 makedirs。 目录不在 → FileNotFoundError → 一键序列第 1 项就崩。 _scratch/ 归档时必须保留一个空的 _check/ 子目录。
  2. _check/harness.js 不是探针，是 run_self.py 的输入 run_self 把产物第 0 块 + harness.js 拼成 selfrun.js 再交给 node（这也是它为什么不读 index.html 的第二个块）。 它不在 SUITE 列表里、文件名也不像探针，最容易被当成孤儿删掉 —— 删了 run_self 立刻 FAIL 计数 1。
  3. README.md 与 阶段性总结.md 是 docfacts.py 的事实源 DECL 表 41 条声明逐条 re.search 这两个文件；找不到即报 STALE 并计入失败（设计原则：判据失效时的绿灯是骗人的）。 删任一份 → docfacts 从「0 不一致」变成一片 STALE。
  4. _scratch/pwa/ pwa-plain/ pwa-sub/ 与 snap/ 可以删，它们会被重建 pwaprobe 通过 assemble.py 的 OUT_DIR 构建，而 assemble.wr() 内部有 os.makedirs；zoomprobe 的 snap/ 是 fs.mkdirSync({recursive:true})。这两处不依赖目录预先存在 —— 与陷阱 1 正好相反，别混为一谈。
  5. index.html / 404.html 是产物，但必须留在 git 里 .gitignore 顶部注释写明：它们是 GitHub 上给访客用的那两个文件，忽略了仓库就不是一个可用的静态站。 「删除后验证」的正确判据也不是「文件不在」，而是「重跑 assemble 后与 git 里的字节完全一致」。

08风险与回滚

可控风险

  • 误删已跟踪文件 → git checkout -- <path> 即恢复（193 个跟踪文件全部有历史）
  • 误删未跟踪的历史资产 → 归档目录原样搬回即可（搬运用 mv 而不是 cp + rm，避免中途失败只剩一半）
  • 探针跑批互相抢端口 → 这是既有约束，与清理无关；并行必然 EADDRINUSE，串行跑
