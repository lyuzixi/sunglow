让 GitHub 连接器拥有写权限

目标：让助手能替你执行「创建公开仓库 sunglow」这类写操作。先解释为什么没有勾选框，再给三条可落地的路径。

先纠正一个说法：「授权时勾选 repo 权限」这个界面真实并不存在。WorkBuddy 里的 GitHub 连接器用的是 GitHub 官方远程 MCP 服务（https://api.githubcopilot.com/mcp/），走的是 OAuth 登录。GitHub 的 OAuth 授权页由服务端固定申请权限，页面上没有任何权限勾选框也不支持手动追加 scope，所以无论重连多少次，结果都一样：读可以，写返回 403。

为什么读得到、写不了

环节实际情况
连接方式Streamable HTTP，直连 GitHub 官方远程 MCP，OAuth 登录
读取类操作正常。查账号、列仓库、搜代码都不需要写权限
写入类操作create_repository 返回 403 Resource not accessible by integration
根因当前令牌未包含 repo / public_repo 作用域；官方 MCP 对缺失作用域采用「调用时动态申请」的机制，客户端若不支持该流程就直接 403
能不能补权限不能。只能换认证方式，或改用其他工具链

可以自查授权记录：github.com/settings/applications（Authorized OAuth Apps / Installed GitHub Apps），但那里只有「撤销」，没有「加权限」。

方案 A：个人访问令牌 PAT（推荐，一次配置长期可用）

把连接器换成用你自己的令牌访问同一个 MCP 服务，令牌上带 repo，写操作立刻可用。

第 1 步 · 打开令牌页面

https://github.com/settings/tokens

Personal access tokens

路径：头像 → Settings → Developer settings → Personal access tokens → Tokens (classic)

选择令牌类型Fine-grained tokens  Tokens (classic)
Generate new token点击 Generate new token (classic)
这里要选 Tokens (classic)。细粒度令牌只能绑定到已存在的仓库，用它建新仓同样会被拒。

第 2 步 · 填写并勾选

https://github.com/settings/tokens/new
Note（备注）WorkBuddy MCP
Expiration（有效期）90 days（到期前记得续）
Select scopes（权限）
repo  Full control of private repositories
勾 repo 会自动带上下级：repo:status public_repo repo_deployment
workflow（可选，要改 Actions 才勾）
gist / notifications（不需要，别勾）
Generate token

第 3 步 · 复制令牌

生成后页面会显示一次以 ghp_ 开头的字符串，关掉就看不到了，先复制保存。然后把它发给对话里的助手，由助手写入本地配置；也可以自己改文件 C:\Users\<你的用户名>\.workbuddy\mcp.json：

{
  "mcpServers": {
    "github": {
      "type": "streamable-http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": {
        "Authorization": "Bearer ghp_在这里粘贴你的令牌"
      }
    }
  }
}

第 4 步 · 启用并验证

  1. 在会话窗口左下角的「+」菜单里打开连接器管理，右上角找到自定义连接器入口，对新出现的 github 点击 Trust（信任），它才会真正生效。
  2. 让助手重试建仓；或自己用下面的命令确认令牌带上写权限：
# Git Bash / PowerShell 均可，看到 repo 就说明有写权限
curl -sI -H "Authorization: Bearer ghp_xxxx" https://api.github.com/user | grep -i x-oauth-scopes
# 期望输出： x-oauth-scopes: repo, ...
到这一步，助手就能执行 create_repository 与后续推送文件了。
安全提示：令牌等同你的账号写权限，只保存在本机配置文件里，不要贴进公开仓库、Issues 或截图；不用时到 GitHub 同一页面点 Delete 即可随时吊销。

方案 B：GitHub 官方命令行 gh（不想在文件里存令牌）

gh 登录时会一次性拿到 repo 写权限，凭据交给系统凭据管理器保管，之后建仓、推代码都能用。

  1. 安装（PowerShell，任选一行执行）：
    winget install --id GitHub.cli
    # 或用 Scoop： scoop install gh
  2. 登录并按提示操作：
    $ gh auth login
    ? Where do you use GitHub? GitHub.com
    ? What is your preferred protocol? HTTPS
    ? Authenticate Git with your GitHub credentials? Yes
    ? How would you like to authenticate? Login with a web browser
    ! First copy your one-time code: A1B2-C3D4
    # 浏览器自动打开，粘贴上方一次性码 → Continue → Authorize GitHub
  3. 建仓（这一步可以直接让助手代跑）：
    $ gh repo create sunglow --public --confirm
    ✓ Created repository lyuzixi/sunglow on GitHub
网页授权那一步同样没有权限勾选框——gh 的 OAuth 应用是固定申请 repo、read:org 等权限的，直接点 Authorize 即可。

方案 C：网页端手动建仓（最快，30 秒）

https://github.com/new

Create a new repository

Owner / Repository name *lyuzixi / sunglow
Description可选，留空也行
可见性 Public    Private
Initialize this repository with Add a README file
Create repository

创建完把地址告诉助手，后续初始化文件、推代码都可以继续交给它（推代码仍需要方案 A 或 B 的写权限）。

三条路怎么选

方案适合谁代价
A · PAT希望助手长期代管 GitHub令牌存本机文件，需自己保管、到期续期
B · gh CLI不想明文存令牌要装一个命令行工具，建仓需助手跑命令
C · 网页只想先有个仓库最快，但助手仍写不了，后续推送还得配 A 或 B

如果只是想马上拿到 sunglow 这个仓库，走方案 C；如果想让助手以后都能直接建仓、推代码，走方案 A。
