## 一、这是什么

一个**单文件 Web 应用**：预测朝霞 / 晚霞（火烧云）的出现概率与观赏质量。

- 产物 `index.html` —— **806,274 字节**，自包含（内联全部 JS、城市表、0.5° 高程网格）。
- 可直接静态部署；地图模块另有**一个可选的**服务端代理端点（`functions/`）。
- 五个模块：单点预报 / 多模型（GFS·ECMWF·光追） / 趋势 / 地图 / 分享卡。

数据全部来自免费公开接口（Open-Meteo 气象与空气质量、阿里云 DataV 省界、腾讯位置服务地图），无需注册。

## 六、已知边界与代价（如实记录）

1. **数据源唯一**：只有 Open-Meteo，无等量替代（卡在「AOD + 边界层/0℃层高度 + 多模型可切 + 无 key/CORS」的组合上）。**免费层仅限非商业**。
2. **限额按来源 IP**：纯前端直连 ⇒ 消耗**访客自己的**日额度（共享 NAT 出口下会与陌生人共用同一份额度）。
3. **地图数据必须用户显式触发**（`#autoMap` 默认不勾选）—— 打开即取会多花 171 次调用。
   **唯一例外：缓存命中自动加载**（B14）—— 上次看过的城市 + 日期开页自动画出来，
   走缓存快路径、零请求，所以不占额度；由 `loadMapData(force, cacheOnly)` 里
   一行 `return false` 硬保证边界。
4. **可信范围**：色面边界 = 采样点**凸包** + 70 km 羽化；**凸包之外那一圈是外推**，起可信度纱（实测覆盖已上色面积的 **21.6%**，与淡出边界、B1 的虚线是同一条线）；取值半径 120 km。悬停卡另给一个**距离**口径（距最近采样点，包内实测最远 85 km）。
5. **单点缓存上限 4 条是实测定的** —— 其上没有别的淘汰机制，超了会吃穿 localStorage 配额，导致**所有**缓存静默失效。
6. **等值线形状精度受值场分辨率限制**（0.05°）：高缩放下折线的直线段会显出来。线宽本身已是屏幕常数。
7. **偏好持久化已落地（B1），第三轮那条"图层开关不持久化"的结论随之作废** —— 当时的拒绝理由是"项目没有通用偏好存储机制，为单个开关开一条 `localStorage` 通道会造成『只有它能记住』的怪异体验"。本轮补上了**通用**机制（单个键 `sunsetbot.pref.v1`，先 9 个、第五轮 UI 起 **14 个**显示状态），这条理由不再成立：五个图层开关现在**都**会记住。应用顺序与"刻意不存的两类"见 §六.12。
8. **地图代理需要一个服务端端点**（Cloudflare Pages Functions，与前端同源 ⇒ 无 CORS）；纯静态部署时地图不可用，页面给的是原因说明而不是报错。
9. **`N_BANDS = 7` 实为偏密**（相邻档对比度只有 1.13–1.36），但**减档治不了低端**（7→5 只把最低档对白底的对比度从 1.05 提到 1.22）—— 档界现在读得出来靠的是等值线压在上面，不是色块之间的色差。
10. **窄屏（≤760px）走另一套布局**，断点宽度写在三处（`template.html` 两条 `@media` + `_p6.js` 的 `TIP_DOCK_MQ`），改一处就要改三处。窄屏下顶部条不再是 sticky、地图提示卡改为贴底通栏（跟随指针在 ~340 px 容器里必然被 `overflow:hidden` 裁掉）；触屏没有 `mouseleave`，所以关闭路径另给了 × 按钮 / 再点同一处 / 点地图外三条。桌面形态不受影响（`mapaudit` 的提示卡断言仍按"跟随指针"那套量）。
11. **移动端布局的一条通用纪律**：任何 `overflow-x:auto` 的滚动容器都要显式 `min-width:0`（`.t-scroll` 已加）——否则它作为 flex/grid 子项会被内容一起撑开，把页面 `scrollWidth` 顶出去，移动端据此放大布局视口，**整页被缩小**。判断用"元素是否越界"，**不要**用"元素是否最宽"：横向滚动表格天生就最宽。
12. **偏好持久化的两条硬约束** —— ① **应用顺序**：`applyPrefs()` 必须在任何"控件初值 / 派生状态"赋值**之前**调用，否则出现"控件写着 A、State 是 B"的**静默错位**（与 `period` 那次同型）；依赖地图 DOM 的两项（经纬网 / 深色底图）延到 `initMap` 末尾，且**必须早于**缓存自动加载，否则先闪一下默认态。② **刻意不存两类**：位置与日期（已由 URL 承载，存了会与分享链接打架）、`mapPeriod`（由 `State.period` 派生，存了会让"地图看晚霞、上方算朝霞"成为常态）。坏值与版本不符一律**降级为默认、不抛错**。
13. **趋势缓存存什么** —— 存**算好的 rows**，不存原始响应：原始响应 ≈ **5 MB** ⇒ 撑爆 5 MB 配额 ⇒ **所有**缓存静默失效；rows ≈ **1.9 KB**。代价是"权重 / 阈值一变旧缓存就错"，用 `TREND_CACHE_PREFIX` 版本号兜住。三个缓存键族共用 `mapCacheSweep` 总闸门，但**"豁免当前地点"恰好相反**：地图 `true`（另有按日期 LRU 兜底）/ 单点 `false`（无其他淘汰机制，豁免会撑爆配额）/ 趋势 `false`。
14. **F4 本地校准的四条边界**（都实测过，改动前先看清楚）：
    ① **只展示、不回改** —— 校准块与结论卡各写各的 DOM（`#calibHead` / `#calibStat` 之外一个字都不碰）；`calibprobe` 拿"标注前后模型指纹逐字段相同"（概率文本 + 大数 + 徽章 + 环 `stroke-dashoffset` + 每个模型数字 + 因素表行数，**136 字符**）把这条断死。**校准被误当成模型输出**是本功能最大的风险，所以数字行里明写"模型在 {lo}–{hi}% 这一档平均报 {pred}%"，主语永远是"模型"。
    ② **样本不够不给结论** —— 累计 `CALIB_MIN_N = 8` 次 **且** 当前分桶 `CALIB_MIN_BUCKET = 3` 次才出数字，之前只显示进度行；"前期只记录不展示"是方案原话。分桶按预测 P 每 `CALIB_BUCKET = 20` 个百分点一档。
    ③ **"没看到" ≠ "没有霞"** —— `a = -1`（无法判断）**不进统计**（分子分母都不进），否则"没出门看"会被算成预报失败，把校准系统性拉低。
    ④ **关掉 ≠ 删除** —— `#calibOff` 只影响入口与展示，已存标注一条不删；清空是另一个按钮 + 二次确认。两件事刻意分开，是为了防止"想安静一下"顺手毁掉几十条样本。
    另两条较小但同性质的约束：**未来时段不给标注**（入口只看 `leadH`，复用既有判据、不新增阈值，`CALIB_AFTER_H = -1`）；**快照模式不出现**（`snap=` 链接是别人发来的，不该让接收者往自己机器上写数据）。存储 `sunsetbot.calib.v1`（≤ `CALIB_MAX = 200` 条，先读→白名单→合并→写，坏行静默降级），`calibOff` 走偏好键白名单。
15. **`calibprobe` 的两条探针纪律**（踩过） —— ① 判"页面就绪"**不能写 `window.State`**：`State` 是顶层 `const`（**词法**全局），`window.State` 恒为 `undefined`，8 个轮询点各自跑满预算 ⇒ 探针被外层超时杀掉两次、**零输出**（SIGTERM / exit 1 / 空文件）——正是本项目「失配必须响」的反面教材。改写 `typeof State !== 'undefined'` 后全程 **~4.3 s**（首轮轮询 221 ms）。② `Page.navigate` 会在**旧文档**仍是 `complete` 时就返回 ⇒ 必须用"导航标记"握手（导航前写随机 `window.__navMark`，之后等 `readyState === 'complete' && __navMark !== 标记`），且超时**抛错**而不是静默继续。

### 13.0 诊断：两个症状、两条根因链

- **"怪"的第一症（大橘饼 + 底图被盖住）**：色面 `.rlayer` 不透明度 0.9 且色阶
  顶端是深红，一块高饱和实心盖住底图 ⇒ 治法是**双降**：色阶换肤（顶端不再深黑红）

  mapaudit/zoomprobe 的"≥200 不透明区"像素断言基线失效）。
- **"怪"的第二症（图例刻度名不副实）**：色阶按**当日值域拉伸**（`scaleT`），
  同一天值域仅 9 分宽时全图挤在色阶顶端 12%，源码注释自述"看上去就是一坨"；
  图例却标着固定 0–100 ⇒ 治法是 **V1 固定绝对刻度**（删 `scaleRange/scaleT`，

### 14.1 经纬网「打开还是看不到」——可见度问题，不是逻辑 bug

诊断路径：先写一次性探针（存根投影 + 墨卡托两种）证明**逻辑全对**（24 条线全在视区内、
开关有像素变化），再量化像素反差：标注 78% 不透明度看得见，**线只有 34% + 半像素
抗锯齿 spread ⇒ 线芯与邻像素反差实测 17.4/255（≈7%）**——形同不存在。
修复走制图惯例**两层画法**：先画 3px 近白光晕（55%）再压 1px 深灰芯线（62%），
光晕保证线与任何底色分离；整像素中心对齐（+0.5）。判据升级为像素级：
「线芯与邻像素反差 ≥28」（实测 38.97）+「芯线与光晕成对」（`line.h` class 区分，
探针数线只数芯线）。教训：**数 `<line>` 元素永远绿得出来，反差不会撒谎**。

### 14.2 云纹「只是颜色深浅」——给云量过半处描边

云影不变（TX_ALPHA=0.3 峰值淡纹），新增 TX_EDGE_AT=50 / TX_EDGE_ALPHA=0.52：
本格与任一四邻「过不过半」不同即是边线格，晴空一侧也描（边界线骑在边界上）。
探针第一版用「四邻必有更淡格」启发式，实测 edgeBad=59：干区孤岛周围的湿格
**全是**边线格（各自都有干邻），四邻 alpha 全同级——那是正确渲染，启发式误报。
改为**逐格精确比对**：按画图公式（边线格 round(TX_EDGE_ALPHA×aF)、普通淡纹
round(TX_ALPHA×v/100×aF)）重算期望值，容差 ±2，须 0 不符。

### 14.3 深色底图并入全局主题

`#dimBase` 复选框删除；`.mapwrap.dark` 唯一来源是 `isDarkTheme()`，执行器
`applyMapDark()`（幂等）挂三个点：`applyMapLayerPrefs()`（initMap 末尾兕底）、

## 17 · 桌面端全屏退不出来：sticky 层叠陷阱（10-19 上午，第五轮反馈）

> 用户反馈："电脑的地图全屏后也无法退出。做成和手机一样的退出交互。"

### 17.1 根因：z=2100 被 sticky 的卡片关在了层叠上下文里

第四轮给 `.mapwrap.fs` 的 `z-index:2100` 看着高于 `.top` 的 60，却**依然被顶栏
盖住**——因为地图卡 `#cardMap` 自己是 `position:sticky`，而 sticky **必然**自建
层叠上下文：2100 被关在卡片内部，整张卡只以 `z-auto` 的身份参与页面层序，反而
排在 `.top(60)` 之下。后果：全屏后 67px 高的顶栏压在地图顶部，左上角那颗退出
胶囊（rect [10,10,96,36]）正被它盖住——**rect 在视口内、display 正常，点击却落在
`.top` 上什么都不会发生**。手机端 `.top` 是 `static`（z-index 不生效），所以手机上
从未复现，这正是"只有电脑退不出去"的原因。

复现手段：起本地 HTTP + 真腾讯地图 SDK（`map.qq.com/api/gljs` 可达，瓦片鉴权失败
不影响控件 DOM），CDP `Input.dispatchMouseEvent` **真实点击**（不是 `el.click()`）
+ `document.elementFromPoint` 命中链，一次命中 `div.top → span → #fsExit`，
桌面端点击无效、手机端命中 `span` 即成功。

### 17.2 修法：全屏期间把卡片自身抬到顶栏之上

`setMapFs` 挂摘 `#cardMap.fsmap`，CSS `#cardMap.fsmap{z-index:2200}`（.mapwrap.fs
同族、仍低于抽屉类浮层）——让整张卡连同卡内的地图层一起盖过顶栏，**桌面就此与
手机同一种退出交互**：地图铺满视口、左上角胶囊真实可点。退出即摘，不影响平时的
粘滞层序。全项目只有 `setMapFs` 一处切 `.fs`，类名挂摘是唯一入口。

### 17.3 探针补硬：合成点击是这次漏检的直接原因

mapaudit L 段原来用 `b.click()` 退出——**合成点击绕过浏览器命中测试**，按钮被盖住
时照样能退，所以这个 bug 一直是绿的。两条新判据（48 → **50 条**）：
① `elementFromPoint` 在胶囊中心必须命中胶囊本身（`fseHit === 'pill'`）；
② 全屏期间 `#cardMap` computed z-index 必须是 2200、退出后回到 auto。
退出动作本身也改成 **CDP 真实点击**（Input.dispatchMouseEvent 经过真实命中派发）。
