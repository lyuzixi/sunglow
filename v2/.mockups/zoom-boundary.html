街区级地名怎么处理

同一个城市（广州）、同一份构建产物、同样一张观测场，只改「底图文字开关」与「允许放大到多近」。 问题的本质不是底图不够好 —— 默认视野（实测跨度 1063 km）下我们的自绘地名完全够用； 真正无字可读的只有放大到街区级（zoom ≥ 12，跨度 < 16 km）那一层，而那一层的字只有腾讯的、且只有中文。

现状

自绘 + 关底图文字

街道网格清清楚楚，一个字都没有。用户放到街区级会彻底失去方位参照 —— 这是「关闭底图文字」的直接代价。

zoom 15跨度 2 km自绘落笔 1底图文字 0
案 A

锁最小缩放（≈250 km）

把最小缩放钉在 zoom 8（跨度 266 km）—— 街区级这一层压根不存在，自绘地名就够用了，而且读起来比底图自带地名更干净。

产品语义上也站得住：57 个网格点最密也隔 20–30 km，街区级本来没有任何霞光数据可看。

zoom 8跨度 266 km自绘落笔 13 / 16底图文字 0
案 A · 繁体参照

同一档，繁体自绘

繁體模式同一档：廣州市 / 香港 / 澳門 / 深圳市 / 珠海市 / 佛山市 … 落笔 15 条。这条无论换不换图源都得由我们自绘（高德国内底图只有简/英，没有繁体）。

zoom 8跨度 266 km自绘落笔 14 / 16底图文字 0
案 C·1

不锁缩放，两层都开

街区级有字了，但出现叠字：底图写「广州」、我们写「Guangzhou」，右下角还压在罗盘控件下面。城市名依旧是中文，等于没解决原问题。

zoom 15跨度 2 km自绘落笔 0（被控件压掉）底图文字 中文，满屏
案 C·2

按缩放自动切换

跨度 > 120 km 时走现状（自绘英文/繁体）；一旦缩进街区级，自动关掉自绘、打开底图文字，图面立刻有字，且没有叠字。

代价只有一个：这一层的字是中文。但这条路任何合规图源都填不满——高德的英文底图要商务工单，繁体它更没有。

zoom 15跨度 2 km自绘落笔 0（自动关）底图文字 中文，满屏
案 B

换高德 + 英文底图权限

没有截图 —— 因为拍摄前提就不成立：

高德多语言是「高级地图能力」，官方要求提交商务工单申请，不是控制台勾选；海外地图同样默认不加载、需工单开通。国内只支持简/英，没有繁体。本机也无 key 可验。

换来的是「街区级英文街名」这一层唯一真实收益，代价是重写 7 个 SDK 触点（`LngLat` 先经后纬、事件名全换、`setBaseMap` → `setFeatures`）+ 探针 20 条地图断言重写。

街区级 英文 ✅繁体 仍自绘审批 工单成本 重写接入层

三个判据

  1. 默认视野不受影响：A 与 C2 在 1000 km 档都和现在一模一样，改动只在「允许放多近」这一件事上。
  2. A 最纯，C2 最自由：A 直接把街区级砍掉，图面永远干净；C2 保留放大能力，只在深处换成中文。两者都不换源、不申请、零新增费用。
  3. B 是唯一能拿到英文街名的路，也是唯一要花钱和等审批的路，而且繁体它救不了 —— 繁体自绘层无论如何都得留着。
这条缺陷已修（2026-10-22）：控件挪到右下角之后，右下角的自绘地名会被罗盘压掉一截（原截图右侧「…nwei」、「Guangzh…」）。 现在把 SDK 控件的实际占位（缩放钮 / 罗盘 / 比例尺 / 腾讯 logo 与审图号）量成避让区：文字先试右侧、撞控件就翻左侧、两边都不行才丢弃，圆点本身落在控件底下的干脆不画 —— 宁可少一条，也不出半截字。 探针新增 3 条断言守它（避让区已量到、英文不压控件、繁体不压控件）。
