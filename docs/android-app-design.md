# 霞光档案 Android · 设计方案 v1

> 目标：把网页端"大气光谱观测站"的品牌气质，压缩成一台**掌上观测仪**。
> 不是网页的缩小版，也不是把 8 张玻璃卡竖着排。

---

## 0. 一句话主张

**一屏读数，一划换日，一点下钻。**

手机上的使用场景是：站在窗边、下班路上、约人之前——**三秒内决定"今晚去不去"**。
所以首屏只回答一个问题，其余全部下沉。

---

## 1. 为什么之前的版本观感差

先承认问题，避免重复：

| # | 问题 | 具体表现 |
|---|------|----------|
| 1 | **所有区块长一样** | 结论、因素、光路、分享、说明全是同款玻璃卡：同圆角、同描边、同 18dp 内边距 → 像后台表单，没有视觉节奏 |
| 2 | **首屏信息过载** | 可信度 pill + 标题 + 结论词 + 长句 + 4 个大数字 + 8 行太阳数据 + 色谱条 + 4 张模型卡 + 脚注 ≈ 3 屏信息塞进 1 屏 |
| 3 | **没有品牌主角** | 网页首屏有实拍天空照 + 光谱仪表盘；App 只剩白字卡片，"大气观测站"的气质全丢 |
| 4 | **层级靠字号暴力** | 到处都是 `headlineMedium`，真正的焦点（概率）反而不突出 |
| 5 | **桌面排版搬进手机** | 一行行"标签—数值"表格、点一行展开说明，在 6 寸屏上是折磨 |
| 6 | **深色下卡片糊成一片** | 深底 + 半透明深卡 + 1px 暗线，边界靠眼睛猜 |

## 2. 四条设计原则

### 2.1 一屏一个结论
首屏只回答"今晚值不值得去"。可信度、模型、因素、光路都不在首屏抢注意力。
判断成本：**3 秒**。超出就是失败。

### 2.2 层级靠光，不靠线
深色模式下，卡片不再是"深色块 + 描边"，而是：
- 背景有极淡的径向光晕（跟着太阳方位偏移）
- 卡片用 `backdrop blur + 极淡白高光`抬起来
- 描边只用于**分组内部**的细分隔，不用于卡片外框

### 2.3 光谱是标点，不是墙纸
品红→琥珀→电离青只出现在四个地方：
1. 选中态（日期、时段、模型）
2. 主按钮
3. 概率数字的辉光
4. 品牌细线（2dp，卡片顶部或标题旁）

其余面积一律用中性色。**渐变用多了就是廉价**。

### 2.4 手机是手持仪器
- 拇指可达区（屏幕下 40%）放操作，屏幕上 60% 放读数
- 触控目标 ≥ 44dp
- 二级信息一律"下钻"，不在首页堆
- 所有可以滑的东西都真的能滑

## 3. 视觉系统（完全继承网页，不发明新色）

### 3.1 色彩

| 语义 | 深色 | 浅色 | 用途 |
|------|------|------|------|
| bg | `#070B14` | `#F2F5FB` | 页面底 |
| bg-elev | `#0B1220` | `#FFFFFF` | 抬升面 |
| card | `rgba(15,23,42,.62)` | `rgba(255,255,255,.72)` | 玻璃卡 |
| ink | `#E9EEFB` | `#111A2C` | 主文字 |
| muted | `#A0B1CD` | `#46556F` | 次要 |
| faint | `#7F8FB0` | `#667287` | 单位/脚注 |
| stroke | `rgba(148,178,232,.14)` | `rgba(40,60,100,.10)` | 发丝线 |
| acc-1 | `#FF4D82` | `#E02D62` | 概率/主强调 |
| acc-2 | `#FF9C3F` | `#E07A1C` | 质量/暖 |
| acc-3 | `#2ED5E8` | `#0F9FBF` | 交互/冷 |
| good / mid / bad | `#5FCE97` / `#E2B45E` / `#F2796A` | 深色版 | 判定 |

### 3.2 字体

| 角色 | 字体 | 说明 |
|------|------|------|
| 数字 / 英文标题 | Space Grotesk（打包子集，约 100KB） | 网页 `--font-display`，是品牌识别的一部分 |
| 中文标题 | 系统黑体（PingFang SC / HarmonyOS Sans / Noto Sans SC） | 不再额外打包中文字体 |
| 正文 | 系统无衬线 | — |
| 数字 | `tabular-nums` 必开 | 概率、分数变化时不跳动 |

字号阶梯（手机）：

| Token | 尺寸 | 用途 |
|-------|------|------|
| display | 64sp / 500 | 首屏概率 P |
| title | 20sp / 600 | 区块标题 |
| headline | 17sp / 600 | 结论句 |
| body | 15sp / 400 | 正文 |
| small | 13sp | 说明 |
| tiny | 11sp | 单位、脚注（字距 +0.06em） |

### 3.3 材质三层

```
① Photo 层：天空实拍照片 + 渐变遮罩   → 只用于首屏 Hero
② Glass 层：blur 22 / saturate 1.35 + 发丝线  → 承载信息的面板
③ Flat 层：无边框纯色面            → 列表行、内部分组
```

卡片最多两层嵌套，不允许"卡里卡里再卡"。

### 3.4 几何

- 卡片圆角 **22dp**，内部面板 **14dp**，胶囊 **999**
- 页面左右边距 **20dp**
- 卡片间距 **12dp**（同组）/ **24dp**（跨组）
- 卡片内边距 **18dp**（信息卡）/ **14dp**（列表卡）

### 3.5 光晕纪律（沿用网页注释里的原话）

> 辉光只给「概率数字」与「结论标题」，其余靠玻璃与发丝线分层。

App 端额外允许一处：**首屏照片自带的太阳光斑**（照片实拍，不额外画）。

## 4. 信息架构

### 4.1 结构

```
底部导航（3 Tab）
├─ 结论      ← 默认页，单点预报（朝/晚 + 任意日期）
├─ 趋势      ← 十日趋势
└─ 观测场    ← 地图 + 排名 + 多地对比

二级页 / 浮层（不占 Tab）
├─ 城市搜索（全屏页，顶部搜索框 + 最近城市 + 定位）
├─ 影响因素（全屏页，13 项分组列表）
├─ 光路细节（底部 sheet）
├─ 分享（底部 sheet：生成图片 / 复制文案 / 系统分享）
└─ 设置（关于、主题、单位、数据来源）
```

**为什么对比不单独占 Tab**：对比的本质是"在地图上选几个点"，把它做成观测场里的一个模式（选中 2–4 个点 → 底部面板展开对比表）比单独一页更符合直觉，也少一个 Tab。

### 4.2 全局状态

城市、日期、时段是**全局状态**，三个 Tab 共享。
切换后所有 Tab 同步（趋势 Tab 会自动以该城市+日期为中心加载）。

### 5.2 首屏 Sky Hero（实拍照片）

首屏主视觉改用**品牌实拍天空照**（与网页 `v2/src/assets/hero-photo.webp` 同源：广州珠江日落）：

- 高度：约 330dp，四角 0，延伸到状态栏后面
- `cover` 裁切，保留天空渐变与城市天际线；焦点放在画面中线偏上
- 三层遮罩保证白字可读：
  1. 左下径向压暗（概率数字所在区域）
  2. 顶部轻压（状态栏、顶栏）
  3. 底部渐深（与内容区衔接）
- 叠加 10% 噪点，避免大图塑料感
- 概率数字与说明叠在左下角，不居中 —— 让出天空

照片在 App 内打包一张压缩版（约 80–120KB，宽 1080 足够 3x 屏），不做轮播、不做懒加载动画。

**职责划分**：
- 照片负责**情绪**（这是"追霞"这件事本身）
- 结论区的天色带负责**信息**（今天几点、窗口在哪、现在到哪一段）

### 5.3 天色带（结论区内）

五段曙暮光条从 Hero 移回结论区，作为一条紧凑的信息条：

- 尺寸：高 46dp，与结论区同宽，圆角 12dp
- 五段色按真实时间比例分配（复用 `core/skyband.ts`）
- 霞光窗口：底部 3dp 橙色条 + 两端短竖线
- "此刻"：1px 白线贯穿色带，轴标下方给"此刻 17:41"
- 轴标：11sp，只写段名（白昼/民用/航海/天文/夜间），窄屏可省略段名只留时刻
- 无霞（无窗口）时隐藏橙条，色带保留 —— 它仍然是"今天的光照时间轴"

### 5.4 指标区与模型联动

指标区采用**双主角**结构，避免概率一家独大：

| 元素 | 规格 | 颜色 |
|------|------|------|
| 概率 P | 50sp Space Grotesk，`tabular-nums` | 白 + 光谱辉光 |
| 质量 Q | 50sp，与 P 并排，间距 30dp | 琥珀 `#FFD08A` + 弱辉光 |
| 等级 | 12.5sp，紧跟"等级"标签 | 按分档：良好绿 / 一般琥珀 / 较差红 |
| 分歧 | 12.5sp，写"分歧 1.0"，不使用符号 ΔI | 白色 |
| 可信度 | 12.5sp，值加粗（与分歧同款） | 标签 55%，值白色 |

行为：
- 未计算：显示 `—` + "点我开始观测"
- 计算中：数字位置显示骨架条，不转圈
- 计算完成：P 与 Q 同时从 0 滚动到实际值（600ms，ease-out），辉光渐亮
- 点击任一数字：切换到下一个模型视角（综合 → GFS → ECMWF → 光追）
- 切换时 **P、Q、等级三者一起交叉淡入**（180ms），不是只换一个数

### 5.5 模型切换

- 4 个胶囊等宽横排，高度 36dp
- 选中：光谱渐变底 + 深色字（深色主题）/ 白字（浅色）
- 未选中：透明 + 发丝线
- 切换时：首屏指标区做交叉淡入（180ms），P / Q / 等级同步更新，不整页刷新

> **实现备注（2026-11-13 回写）**：实际落地为 `native/.../ui/screens/HomeScreen.kt` 的**四张并列模型卡**（点击联动 Hero 的 P / Q / 等级 / 分歧 / 可信度一起切换），不是本节写的 4 个横向胶囊；`docs/android-roadmap.html` 与后续方案均按「四模型并列卡」验收。胶囊规格保留为早期设想，不再作为实现判据。

### 5.6 三宫格

只留**决定"去不去"的三个数**：

| 格 | 内容 | 为什么是它 |
|----|------|-----------|
| 云型 | 层积云 / 高积云… | 决定"有没有戏" |
| 云底 | 1.30 km | 决定"颜色够不够红" |
| 最佳窗口 | 17:20–17:45 | 决定"几点出门" |

其余 8 项太阳参数全部下沉到「光路细节」。

### 5.7 状态设计

| 状态 | 表现 |
|------|------|
| 首次进入（无数据） | 照片与天色带用当前时刻的真实光照（不用预报），中央显示"下一场霞光，算一下" + 主按钮 |
| 取数中 | 数字位置骨架屏，照片保持，不闪白 |
| 成功 | 数字滚动 + 光晕亮起 + 结论句淡入 |
| 无霞（P < 15） | 照片降饱和并压暗，结论句"这次希望不大"，不显示红色警告；天色带保留 |
| 失败 | 照片保留，卡片区一行"没取到数据" + 重试按钮 |
| 缓存 | 页脚"缓存 · 4 分钟前" + "重新取数" |

### 6.2 交互

- 横向滑动最佳窗口卡（peek 露出第 2 张，暗示可滑）
- 点任意一天 → 切回「结论」Tab 并载入该日期（带转场：日期胶囊高亮 + 数字滚动）

## 7. 观测场 Tab

### 7.1 结构

```
┌──────────────────────────────────────────┐
│  ┌────────────────────────────────────┐  │
│  │                                    │  │
│  │      地图（全屏，底图压暗）          │  │
│  │    thermal 热力 + 光路样带叠加       │  │
│  │    · 观测点 pin                     │  │
│  │                                    │  │
│  └────────────────────────────────────┘  │
│   [朝霞][晚霞]  [综合][P][Q][分歧]        │  ← 浮动在地图上方
│                                          │
│  ╭──────────────────────────────────────╮│
│  │  ≡   最佳观测点  香山 · 18 km · 76%   ││  ← 可拖拽底部面板（peek 96dp）
│  │  ──────────────────────────────────  ││
│  │  排名  1  香山      76%  良           ││
│  │        2  百花山    71%  良           ││
│  │        3  灵山      68%  中           ││
│  ╰──────────────────────────────────────╯│
└──────────────────────────────────────────┘
```

### 7.2 交互

- **拖拽面板**：peek 显示最佳点摘要，上拖到半屏看排名，再上拖全屏
- **长按地图**添加自定义观测点（加入对比）
- **点 pin**：pin 上方浮出小卡（名称、距离、P/Q），点卡片进入「结论」Tab 查看该点
- **双指缩放**地图，单指拖动；地图到顶底时手势自然传递给面板
- **对比模式**：面板顶部切到"对比"，已选 2–4 个点纵向罗列 P/Q/云型/窗口，支持左右滑动切换指标

### 7.3 性能约束

- 底图统一压暗（深色 `#0B1220` 遮罩 0.55），避免地图花哨抢色
- 热力/样带用 Canvas 叠加，不引入额外的地图 SDK 图层
- 首次进入不自动加载全量样带（省流量），点"加载"才开始

## 8. 影响因素页（二级页）

### 8.1 分组，而不是 13 行平铺

```
云与光
  云量类型与覆盖度   层积云 · 低 0%        [不利]  38
  云底高度          1.30 km              [中性]  55
  云边界距离        无明显云边界           [不利]  20
大气通透度
  气溶胶 AOD        0.31 (550nm)         [中性]  60
  能见度            24 km                [有利]  82
  相对湿度          55%                  [有利]  76
稳定性
  气压稳定性        0.45 hPa/h           [有利]  70
  对流活动          CAPE 0 J/kg          [有利]  85
模式一致性
  ΔI 分歧           1.0                  [有利]  80
```

- 每行：名称 + 值 + 判定 chip + 右侧小分数
- 点击行：就地展开 2–4 行说明（不跳转、不弹窗）
- 分组标题用 11sp 大写字距，比正文更弱
- 顶部一个"综合评分"环（可选），给出 0–100 的总分

### 8.2 为什么不在首页

13 项是"诊断"，不是"结论"。手机首屏放 13 行 = 把用户推走。

## 9. 分享

底部 sheet，三块：

1. **图片卡**：竖版 1080×1440，天色带 + 概率 + 结论 + 城市日期 + 品牌角标；生成后可保存/系统分享
2. **文案**：一句话（"今晚 17:32，北京晚霞概率 72%，良好"）+ 复制按钮
3. **链接**：短链 + 二维码（可选）

生成图片在本地完成，不上传。

## 10. 交互与动效规范

| 场景 | 时长 | 曲线 |
|------|------|------|
| 按钮/胶囊按压 | 120ms | linear |
| 状态切换（模型/日期） | 180ms | `cubic-bezier(.16,1,.3,1)` |
| 卡片入场（首屏 stagger） | 420ms | 同上，延迟 60ms 递增 |
| 数字滚动 | 600ms | ease-out |
| 面板拖拽 | 跟手 | spring（damping 0.85） |
| 主题切换 | 320ms | crossfade |

触觉反馈（`HapticFeedback`）：
- 切换日期 / 时段 / 模型：`TextHandleMove` 轻震
- 展开因素行：`LongPress` 轻震
- 分享成功：`Confirm`

手势：
- 首页下拉 = 重新取数（带光谱色进度环）
- 首页左右滑 = 切换日期（可选，默认关闭，避免与系统返回手势冲突）
- 二级页系统返回 = 回上一级；首页再按 = 退出

## 13. 验收清单（怎么判断"不丑"）

- [ ] 首屏（不开滚动）能看到：概率、结论、三宫格
- [ ] 任意一屏没有"三张以上完全同构的卡片"连续堆叠
- [ ] 深色模式下不开描边也能分清卡片边界
- [ ] 光谱渐变在一屏内出现不超过 3 处
- [ ] 所有长文本（>40 字）都在折叠区或二级页
- [ ] 单手拇指能点到所有主操作
- [ ] 概率数字是屏幕上最亮的东西
- [ ] 与网页并排看，一眼能认出是同一品牌
