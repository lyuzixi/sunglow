## 5. 自定义底图样式的发展空间（评估 + 设计拍板，V2）
**先修正上一节的错**：高德「自定义样式免费」说过头了 —— 基础配色有免费额度（社区反馈「只能免费定义一次」），**纹理要开通会员**；官方产品页原文：*「免费用户可使用离线加载，升级服务后可使用在线加载，JS API 只支持在线加载」*。腾讯也不是不给：GL JS 本身有 `mapStyleId`，**免费 4 套模板含深色「墨渊」（`style2`）**，卡点是**样式必须先在控制台与 key 绑定**（一个 key 最多绑 3 个）。所以我们深色用 `invert` 反相，不是没有答案，是**没有 key**。

**能力对照（官方/社区混合，标注可信度）**：腾讯 4 大类 44 小类（背景面/背景线/道路/POI），属性含颜色/透明度/描边/**层级 level**（高德没有）；高德 7 大类 44~100+ 种（区域面/建筑/水系/天空/道路/**标注独立一大类**/行政边界），属性含显隐/填充/描边/不透明度/**纹理**（陆地/水系/建筑/天空/景区 5 类可上传，要会员），另有图片取色、360° 旋转 + 俯仰、第三方图层。

**六个发展方向（按值排序）**：A 深色去掉反相换真墨底（白赚）；B 浅色底图退到背景；C 三语地名统一（工程收益 > 视觉收益）；D 纹理（陷阱：要会员、1000km 下变噪点、瓦片变胖）；E 语义化底图配色（**要顶住**：绝对刻度 0–100 要求底图中性，带色就是污染读数）；F 零价值项（三端共用/360°旋转俯仰/第三方图层）。

**五项拍板**：① 底图角色 = **退到背景**（色面唯一主角）；② 深色 = **自建一套色板**（与浅色共用，只换明暗档），不用官方墨渊；③ POI 与地名 **全关，三语都走自绘**（自绘层已有分级/避让/控件安全区，接管简体是顺水推舟）；④ 落地 = **样式优先、滤镜兜底**（与 `sdkFail` 降级自绘同一思路）；⑤ 除海陆外保留 **水系 + 省界**，道路与 POI 全关；⑥ 远景密度回到**约 30 个**（现实现只有 8 个省会，与当时「远看约 30 个」拍板不符，要一并纠正）。

**实测发现（都要记住）**：
- `baseMap.features: ['bg']` = **一张纯米色纸**，连海陆都没有（极端退让方案，但海岸线是霞光判断必需，不用）。
- `['base']` 含海陆 + 水系 + 省界 + 道路，**道路没有独立 features 开关** → 「留水系省界、关道路」只能靠自定义样式，这条边界是硬的。
- **滤镜兜底参数（已实拍验证可用）**：浅色 `saturate(.3) brightness(1.04) contrast(.94)`（关键：**别压对比**，硬压会让路网变成唯一深色结构、反而更抢眼）；深色 `invert(1) hue-rotate(180deg) grayscale(.9) brightness(.82) contrast(.85)`。**顺序不能反** —— 先 invert+hue-rotate 归位再 grayscale，否则纯蓝的海洋反相成暖褐，整张图变暖褐色。
- 自定义样式的**隐性收益**：腾讯 logo / 审图号 / 比例尺是 SDK 单独渲染的 DOM，样式只管瓦片 → 换样式后这些合规标识回到原色。现在深色下它们全被滤镜染色了。
- 对照板 `.mockups/map-tone.html`（现状浅/兜底浅/现状深/兜底深 四格 + 「有 key 后还能补四件事」表）。

**状态**：设计已钉死，代码未动。下一步 = 改 `.map-host` 滤镜、`baseMapConf` 三语统一 `['base','building2d']`、自绘接管简体、远景密度提到约 30、加 `mapStyleId` 可选项（有 key 时优先）+ 探针补断言。样式部分**本地无法验证**（无 key），只能线上确认。

## 8. 修地图拖动卡顿：热力场缓存（V2）
用户报「地图使用起来卡顿」，grill-me 三轮定位：**拖动/缩放时**、**载入色面后才开始卡**、主题/设备不限 → 病因钉死为 `paintField` 在地图每个事件帧全量重算（≤16 万格 × 57 点 IDW + 云纹插值 + marching squares），而色面在地理空间里根本没变。

**拍板路线**：「缓存色面拖动只平移」+「允许缩放中短暂发糊」（主流地图同款体验）。

实现（`maprender.ts` 拆两段）：
- `buildFieldImage(ctx,o)`：一次性算好**地理栅格**并全部落进 `FieldCache`（新接口，`newFieldCache()`）——离屏 canvas（热力场 ImageData→off canvas）、云纹 off canvas、等值线线段 `Float32Array`（`segs`/`nSegs`，**几何与绘制分离**，描边颜色在贴图段按当前主题现给）、以及 `latTop/lonLeft/step/cols/rows/pts` 元数据。计算式与旧语义逐字同源，只把「每帧重算」改「缓存复用」。
- `paintField(ctx,o)`：缓存命中（`samePts` 用 `Object.is` 比 lat/lon/v/cld）→ 只按当前投影重新求仿射矩阵 A/B/C → `ctx.transform` + `drawImage(cache.field/cloud)` + 线段重放。拖动/缩放每帧开销 = 两次 GPU 贴图 + 一把线段，不再有插值。
- 失效即重建：pts 任一字变（切周期/维度/模型/日期/网格）、`showCloud` 开而无云纹缓存。**主题不需要失效**——HEAT_RAMP/云纹/等值线颜色全是常量（绝对刻度），`dark` 只影响描边 rgba 与栅格网线，在绘制段现取。
- `MapView.vue`：模块级 `const fieldCache = newFieldCache()`，`paintField` 调用传入 `cache`；SDK 事件监听（`bounds_changed/zoom_changed/center_changed/drag/idle` → `schedulePaint`）一行没动。

**验证**：

- 目检 `.mockups/.shots/field-after-cache.png`：色带/等值线/云纹/虚线圈/数值标注全正常。
- 探针首跑曾在自绘月历段 `ev(CAL_GEO)` 崩（ab 瞬时失败，非本次改动相关），重跑即过。

**边界与遗留**：

## 11. 「加入对比」真手点不了的第二个根因：SDK 层盖住定格卡（V2）
用户复查：点了「加入对比」没真加入。上一节的探针用 `el.click()` 直发——**绕过命中测试**，违反「可点必须 elementFromPoint 验」的老规矩，所以全绿漏网。elementFromPoint 实测：按钮中心命中的是腾讯 SDK 的无类名交互 DIV（`DIV. > DIV.map-host > .map-box`），不是按钮。

**根因（量实）**：SDK 交互容器自带 **z-index:1000**（canvas z=2），`.map-host` z-index auto 不创建层叠上下文 → SDK 的 1000 与 `.pincard` 的 41 在 `.map-box` 的层叠上下文里同场竞争 → 1000 赢，定格卡整体被盖住，真实点击全落 SDK 层。悬停 `.tip` 是 pointer-events:none 从不需要命中，所以这坑一直没暴露；定格卡是第一个要被点的卡。

**修法（结构性，原版「#map 须 position:relative;z-index:0」同款）**：`.map-host{z-index:0}` —— 创建层叠上下文，SDK 内部任意 z 都封在 0 层里，`.overlay`(画布)/`.tip`(40)/`.pincard`(41) 全部回到上层。副作用评估：SDK 控件（+/−、罗盘、logo）从「盖在画布上」变为「被画布半透明色面轻染」——可接受；地名避让（chromeRects）不受影响。

**验证**：命中测试脚本（elementFromPoint + 完整 mousedown→mouseup→click 派到顶层元素）：修前 `topChain:[DIV., DIV.map-host,…]`、msg null；修后 `topIsBtn:true`、msg「已加入对比」、对比卡 1→2。typecheck ✓ / build **796.0 KB** 零外链 / ui **251/0**（选点段 +1 条 elementFromPoint 断言，且「点按钮入列」改为真实语义点击）/ tz 28 / consist 16；全 LF。

**探针两个新教训**：
1. **可点断言必须 elementFromPoint**：任何「点了某按钮」的探针断言都先断命中（`t===btn || btn.contains(t)`），再派发完整序列到 elementFromPoint 找到的顶层元素——el.click() 直发只能当兜底。
2. **elementFromPoint 对视口外坐标恒 null**：断言前先 `window.scrollTo({behavior:'instant'})` 把目标滚进视口，否则探针页面停在页顶时必假失败。
3. **Vue 渲染异步**：dispatch click 后同步读 DOM 是旧的——读 msg/行数必须隔 wait。

## 12. 「点击广州市弹邻市」：吸附半径超 Voronoi 半区 + 定格卡吞点击（V2）
用户报「点击广州市不显示广州市」。grill-me 定位现象：**弹卡但名字不对，是佛山/东莞这类周边市**。

**根因一（几何，主因）**：吸附是「取最近点」没错，但固定 60px 吸附圈 > 半环距——默认视野（跨度 1063km、画布 480px）网格环距仅 **54px**，点击广州市标签偏 30px 就几何上更靠近邻市格点。偏移点击矩阵实测：偏 30px 弹「澳门附近/云浮市附近」、35px 弹「贺州市 东 60 km」——完全复现。之前为救「点间死区」把半径从 26 提到 60，矫枉过正。
**修法**：半径随视野自适应且**不超过半环距**——`ringPx = MAP_GRID_KM/spanKm*画布高`；`pick=clamp(ringPx*0.5, 22, 90)`、`hover=clamp(ringPx*0.42, 16, 56)`。偏差出圈=不吸附（无反应），绝不弹意外地名。

**根因一的补丁（主场特权）**：半环距在远景只有 27px，「点广州市」稍有偏差仍会弹惠州——几何诚实但违背用户意图（用户点的是底图上「广州市」那个名字）。对**本市格点（0 环）放宽到 0.95×环距**：点本市附近必弹本市；其它格点无同名歧义，维持诚实半径。**坑：本市格点不能用 `lat===gridCenter.lat` 严格匹配**——网格中心经浮点运算后与 city 坐标差微值（实测 `exact:false`），改用「屏幕上距本市投影最近且 <8px 的格点」识别。

## 14. 热力图的「一堆规整圆」= IDW 牛眼伪影（V2 分层重做色面）
用户截图报：色面上到处是一个个规整的圆，一大块有晚霞的地方中间突然空出一个圆 —— 问「晚霞分布真的这样吗」。

**取证（决定性）**：把 57 个采样点按真实投影叠回地图截图（`.mockups/_evidence.cjs` + PIL 打十字与 60km 圈）——**每个圆的圆心精确落在一个采样点上**，圆心处数值就是该点采样值（页面上「数值直标」写着 85/52/40/14/8）。根因三层：
1. 采样网格 120km，1000km 视野下屏上只有 54px 间距；
2. IDW 正则化尺度 `d²+900`（≈30km）= 格距的 **1/4** → 每点周围长出一个半径 30–60km 的「主场盘」，盘内被该点钉住、盘边陡降（实算：邻点距 120km → 主场半径 60km → 屏上直径 99px，与截图圆尺寸吻合）；
3. 7 档量化把盘边切成硬边圆环。
另有数据侧事实：6 个点的值完全相同（v=8.9、P=8、Q=10），在广东西南沿海连成一片低值区（不是单点圆洞）。

**grill-me 七问拍板**：①方向=分层（趋势 + 异常点单独标）；②高低异常都标；③阈值=留一法残差 15 分；④高值=渐变光斑、低值=虚线小圈（低值画色斑等于挖洞）；⑤光斑 40km、中心=真实分数；⑥7 档硬边不变；⑦云纹跟随趋势、等值线画在趋势场；外加「光斑单独一层不进量化」（否则被切成同心色带又造回圆）；相邻异常点连成带。

**落地**（`maprender.ts` + `MapView.vue`）：
- `FIELD_TREND_KM=120`（= 采样格距）替掉 900；**删掉「精确命中采样点」分支** —— 那是牛眼的第一推动力。
- 异常点用**留一法**残差判定（拿自己算趋势会把趋势抬高、残差被压小，厦门 85 那种孤峰会漏判）。O(n²)=3249 次一次算完，进 cache。
- 光斑单独一层（`paintSpikes`，连续径向渐变，不进栅格/不进等值线）；半径自适应 = clamp(到最近异常点距离×0.5, 40, 70)km —— 一条高值带上相邻点相距 120km→60km，两核相接连成带，否则排成一串珠子。
- 云纹同步趋势口径；`trendValueAt()` 导出供探针 + 钩子 `__gcTrend` / `__gcFieldProbe` / `__gcPts().spikes`。

**验证**：真实数据 —— 趋势面在采样点 vs 40km 外最大只差 **3.3 分**（旧算法 20–30）、晚霞 7 个异常点 / 朝霞 10 个、圆彻底消失、粤东高值带连成一条；合成数据 —— 85 分孤峰放在一圈 10 分里，峰上趋势 25 分（旧算法 61）；typecheck ✓ / build **806.3 KB** 零外链 / ui **276/0**（新增 3 条守卫）/ tz 28 / consist 16；全 LF。

**坑**：①`ev()` 包 `JSON.stringify`，多步语句要走 `ab("eval",…)`；②PIL 只在系统 Python 3.14（managed 3.13 没有 numpy/PIL）；③截图坐标要先把 `.map-box` 滚进视口居中，否则 `getBoundingClientRect` 与截图裁切对不上；④离线复现必须用真实 dump 的采样值，否则说服不了人 —— `_dump.cjs` 钩 `__gcPts` 落 `.mockups/.build/pts.json`。
