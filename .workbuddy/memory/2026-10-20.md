## 交付形态补救（同日二轮反馈）
- 用户双击 `v2/index.html` 看不到内容 —— 根因：Vite 源码入口引用 `src/main.ts`，且 ES module 产物在 file:// 下被 CORS 拦截（多文件与"双击即开"天然互斥，交付时未摆出这个矛盾）。
- grill 定案：**双轨产物**。`npm run build:standalone` → `v2/standalone.html`（vite-plugin-singlefile，JS/CSS/西文字体全内联 590KB，断网双击即开，file:// 实测出数）；`npm run build` → `v2/dist/` 多文件照旧（部署用）。
- `v2/index.html` 的 `#app` 内置指引页（Vue 挂载后被替换；JS 跑不起来时留下）——"开错文件"时就地给三条正确路径，别再让交付物看起来是空白。
- 西文字体只 import latin 子集（中文走系统字），多文件 CSS 35KB→26KB。
- 教训：**"标准多文件产物"与"双击即开"必须在交付说明里显式互斥**；用户心智里"打开 index.html 就该有东西"对任何 HTML 交付都成立。

### v3 实现中踩的坑
- **agent-browser 的 session 目标漂移**：跨 Bash 调用后 eval/screenshot 会打到 about:blank（截图全白 3.3KB 假象），`open` 输出的标题却是对的。对策：每条 Bash 链都以 `agent-browser open` 开头；截图用绝对路径（CWD 漂移会把相对路径写到别处）；关键验证走 `window.__v3` 状态句柄（state.ts 挂的调试柄）而不是看图。
- **agent-browser 的 click 打不到 Vue @click**（元素命中检查都过了但 handler 不触发；JS `.click()` 立即触发）——自动化点击验证要区分「工具点击」与「JS 点击」，后者才反映应用真相。
- **Node 22 直跑 TS 探针**需要解析钩子把 `./x` 补成 `./x.ts`（probes/register.mjs + ts-resolver.mjs）；vite/tsc 的 extensionless import 在 Node ESM 下会 ERR_MODULE_NOT_FOUND。
- 画布径向渐变的 alpha 渐隐不能对 `rgb()` 字符串做正则换 alpha（只换掉最后一个通道）——在 ramp.ts 里直接产出 `rampColorA(v, a)`。
