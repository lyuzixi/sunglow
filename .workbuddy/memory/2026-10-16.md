### 路径（与 2026-10-12 那次同一条，但换成了 Git Data API）
沙箱里 **git 到 github.com 仍然不通**（`git ls-remote` → `CONNECT tunnel failed, response 502`），
而 `urllib` 到 `api.github.com` 通。所以走 REST。
这次**不用 contents API 逐文件 PUT**（那样三个文件 = 三个提交），改用：

    GET  /git/ref/heads/main            → HEAD
    GET  /git/commits/{head}            → base_tree
    POST /git/blobs                     （每个文件一个，base64）
    POST /git/trees  {base_tree, tree}  ← 以远端树为底，只覆盖这三个路径
    POST /git/commits {tree, parents:[head]}
    PATCH /git/refs/heads/main

⇒ **一个提交**，且不会动到远端树上其它文件。脚本 `~/.sunglow-sync.py`（可复用）：
凭据取 `~/.workbuddy/mcp.json` 的 `Authorization: Bearer ghp_…`（**值是整串，要 `split()[-1]`**），
不进 argv、不打印。自查判据照旧：**远端 blob sha1 == 本地 `sha1("blob <len>\0"+原始字节)`**。
结果：index 671,972 / 404 24,505 / README 24,685，三个都逐字节相同 ✔。

### 顺手发现并修掉的一个**线上**缺陷
Pages 开在 **`https://lyuzixi.github.io/sunglow/`（子路径）**，而此前 404.html 是按默认
`SITE_BASE=/` 构建的 ⇒ 页内"返回首页"跳到 **域名根**（`lyuzixi.github.io/`），不是本站。
改按 `SITE_BASE=sunglow python assemble.py` 构建（404.html 24,489 → 24,505 字节，写 `/sunglow/`）。

**`404probe` 相应改成从产物自己的 `data-home` 上读站点根**，不再写死 `"/"`：
```js
const SITE_BASE = (readProduct().match(/data-home="([^"]*)"/) || [,"/"])[1];
```
否则按子路径一构建，"首页链接指向站点根"那条就假失败。服务器桩也要认 `HOME + "index.html"`。
已实测：线上深路径现在返回 `data-home="/sunglow/"`、`href="/sunglow/"`。
**以后换到域名根部署就直接用默认构建**；README 已记下这条。
