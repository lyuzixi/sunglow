## 「改了就会坏」的硬约束
1. `geomSig()` **只校验点集**。改几何字段（分辨率/分段/字段增删）必须**升 `MAP_CACHE_PREFIX`**，否则旧缓存被喂给新结构。
2. `exact` 是 `Int16Array` 存点下标 → 采样点 ≤ **32,767**（当前 57）。
3. 权重必须 Float64（Float32 的 ~1e-7 误差破坏逐位回归基线）；段内候选必须**按原 pts 下标升序**写入，浮点求和才可复现。
4. `FIELD_STEP` 与 `FIELD_BLUR` 必须同步（物理半径 = STEP×BLUR；现 0.05°×2 格 ≈ 11 km）。
5. `LABEL_TIERS` 只在跨台阶时重建 DOM（`syncLabelTier`）；拖动时不得重建。
6. `dlT` 必须按 **(列,点) 转置**存，取值层内循环才有 cache 局部性。
7. `API_TZ="auto"` 是全应用唯一时区口径，`MAP_TZ` 必须等于它。
8. **默认城市只有一个来源**：`_p5.js` 的 `State` 初值（广州 `23.1291,113.2644/广东省`，与 `PRESETS` 一致）。`initUI` 里**只允许一次** `setLocation(State…)`。改默认城市 = 只改 `State` 那 4 个字段。
9. **额度纪律**：自动取数先算账。首屏只取单点；地图数据必须**用户显式触发**（`showMapIdle()` 的按钮或勾 `#autoMap`，**默认不勾**）。**别把 `loadMapData()` 加回 `initMap` 末尾**。
   **B14 有界放宽：已有缓存就自动画**（`autoLoadMapFromCache()` = `loadMapData(false, true)`）。放宽的边界恰好落在"**发不发请求**"这条线上 —— 上面那条纪律的本意是"别让取数随页面打开自动发生"（首屏 520 个加权调用里地图占 456，等于把全站每天的开页次数砍到二十次），而**缓存命中根本不发请求**，用户上次看过的城市 + 日期没有理由每次重开都再点一次。
   实现：`loadMapData(force, cacheOnly)` 的 `if (cacheOnly) return false;` 位置在**两条缓存快路径之后、任何网络调用之前** —— 于是"自动加载不会烧额度"由**那一行**硬保证，而不是靠调用方复制一份命中条件去跟快路径对齐（镜像条件迟早漂移，那正是本条纪律最怕的事）。返回 `true` 表示真的画出来了，调用方据此决定要不要显示待加载引导。
   挂点**只有两个**：`initMap` 末尾（首屏）与 `mapOnPlaceChanged` 的**作废分支**（换地点）。**绝不能挂 `setLocation`** —— 小幅移动（≤ `MAP_KEEP_KM`，如 60 km）时地图并未失效，在那种状态尝试自动加载、又恰好没缓存，会把一张好图换成"待加载引导"（localgrid 的「小幅移动不弹待加载引导」断言当场抓到过这个回归）。
   判据（localgrid 6 条）：用 `Fetch` 拦截统计"**坐标数 ≥ 50** 的批量请求"（地图取数 57 / 单点 1 / 趋势 34 ⇒ 这是"这批是不是地图取数"的唯一可靠特征），做两次加载对照 —— 无缓存首屏（引导显示 + 0 批量请求 + 无数据）、有缓存首屏（自动画出 3 条带 + 0 批量请求）；外加一条**判据自检**（显式取数必须被计数），否则"零请求"断言会因计数失效而静默变绿。
10. **`MapMod.ok` 是「地图对象建成」不是「数据已就绪」**；`MapMod.loading` 是"提示条是不是进度条"的状态位，`showMapIdle`/`mapShowError`/`mapSetLoad` 三处都维护（**别用文本内容猜**）。判有无数据用 `mapSet()` 空否或 `strips.length`。
11. **429 文案必须走 `friendly` 字段**，三条链路（`runForecast`/`loadTrend`/`loadMapData`）都撞它；两类处置相反（日额度耗尽劝退 / 短时限流重试），漏一处就把用户引向错误方向。
12. **点集不是编译期常量**：`mapPts()` 随查询点变，由 `MapMod.gridC`（**网格中心**）决定，**不是** `State.lat/lon`；以中心为准才保证"建网格的中心"＝"取数的中心"。
13. **缓存键两道闸门缺一不可**：版本号 + `mapKeyOf()` 的坐标维度。三个入口统一走 `mapKeyOf()`，**任一处拼前缀就"写进去读不到"或"读到别人的"**。
14. **LRU 只按日期计数、跨地点管不到**（淘汰用**当前**坐标拼键）→ 必须有 `mapCacheSweep()` 跨地点总闸门（`MAP_CACHE_MAX=6`），否则 localStorage 涨到 5 MB 后静默失败。
15. **「多远之外不再可信」只有一个来源**：`MAP_IDW_MAX === FIELD_REACH_KM` 且 `TIP_RANGE_KM === FIELD_REACH_KM`（写成**表达式**）。曾三个数 ⇒ 一条**图上透明、悬停却有值**的环带。
16. **`gridName` 三档 + 兜底去重**：`<15 km` 城市名 / `<CITY_NEAR_KM=60`「附近」/ 更远「城市+8方位+距离」。8 方位+10 km 取整在 400 km 处不够 ⇒ `buildLocalGrid` 建好点集后**必须再去重**（后来者退 1 km 精度）。**别用"加到 16 方位"代替去重**。方位计算经度差必须乘 `cos(lat)`。
17. **悬停两重节流同时保住**：rAF 合并（`hoverRaf`/`hoverLL`）+ DOM 去重（`tipHtml`）。`mouseleave` 必须调 `cancelHover()`。量它时计数要在 `click` **之前**读走（`onPick` 的 `showMapTip` 不过 rAF）。
18. **「模型分歧」维度与所选模型解耦**：`dimOf` 要在取 `mk` **之前**分流（`if (dim==="dv") return divergeOf(o);`），`#mapModel` 置灰。极差只取 gfs/ec/rt 的 `mixedIndex(P,Q)`；**少于两套有值时返回 `null` 而非 0**。连带标签/排行榜/下钻/悬停卡。**零取数**。
19. **可信度纱是独立画布，绝不能动色面像素**：读 `MapMod.strips`，纱在 `.conflayer`。`f.dkm = √aMin×6371.0088` 挂几何、与维度/模型无关（它仍被悬停卡的 `confOf(km)` 用着）。
   **边界＝凸包外（`sd > 0`），不是 `dkm > FIELD_FULL`** —— 这是 C2 改的，原因是一次**被边界改造打断的不变量**：判据 `dkm > FIELD_FULL` 是**凸包改造之前**的写法（当时色面边界＝「距最近点 FULL(75) 起淡出、RANGE(240) 归零」，与「起纱」碰巧重合）；换凸包后淡出边界挪到凸包上、判据没跟着走，覆盖率从 46% 掉到 **1.3%** —— 而 `buildConfStrips` 的注释里其实一直写着「纱的边界另取『凸包外』」，**代码与注释一起跑偏了**。
   实测证明**这不是阈值问题**：广州默认取景（栅格 217×200、已上色 31,342 格）下，包内 `dkm` **最大只有 85.3 km**（≈ 格心到最近格点 `120 × 0.707`）⇒ `dkm > 90` 只可能在羽化带里触发；而羽化带里 `dkm` **最小只有 1.4 km** —— 贴着凸包顶点外侧一点**明明已经是外推**，`dkm` 却是 1.4 km。⇒ **`dkm`（离最近观测点多远）根本无法表达「外推」（在不在采样区里）**，调阈值只是在「错得少一点」与「错得多一点」之间挑。
   落定后：判据用与 `evalField` **同一套局部等距投影**算 `sd`；覆盖率 1.3% → **21.6%**（`mapaudit` J 段，三亚取景 5,967 / 27,612 格）。图上现在三样东西**永远对齐**：B1 的虚线、纱的内边界、色面淡出的内边界。审计：`mapaudit` J 段「可信度纱覆盖＝凸包外」＋ `cdp.js` 的 `veilWant === veilGot`（两者同源）。
   `D[q+3] = 96`（纱的不透明度）**一直跟着边界改**，从来没调低过 —— **不要用「调透明度」去修覆盖问题**。
20. **图层次序**（全在 `.mapwrap` 层叠上下文，不依赖 DOM 顺序）：0 底图压暗 / 1 色面 / **2 等值线+经纬网** / 3 纱 / 4 方位距离环 / 5 数值直标 / 6 图钉 / 7 加载遮罩 / 20 提示卡。新增叠加层一定挑一个号，并**同步三处**：template 里那张注释表（全项目图层号的唯一来源）、各层的 `z-index`、`.mapwrap.dark` 的 filter 名单（漏一处 → 深色底图下该层颜色被翻错）。
21. **`renderPins` 靠签名兜底**（勾选+点数+值场中心+查询点）。清空 `pinLayer` 必须**同时把 `pinSig` 置空**，否则永不重建。
22. **`#mapDateSel` 标记只写 `option.textContent`**，`value` 不能动；`（今天）/（明天）`存 `option.dataset.base`（只该一处定义）。刷新四处：打开页面 / 落内存 / 缓存落盘（成败都刷）/ 换地点。
23. **样带必须与单点同构**：`analyseTransect` 的 `step = transect[1].d − transect[0].d`，`dFar = 最末点.d + step`。步长不同 ⇒ **同一片云算出不同云边界距离**。动点数/间距必须同步 `MAP_AZ_KM`（= `TRANSECT[末]` = 400）并升缓存版本。
24. **`consist` 与 `ensConfOf` 同一把尺子**：都由 `dvI = spanOf(parts.map(x=>mixedIndex(x.P,x.Q)))` 导出（`consist = clamp(100−dvI×1.9,0,100)`）。**别再用 `spread`（P 的极差）** ⇒ 同屏"一致性 62%"配"可信度 高"。四处同源：地图 `dv` 维度、结论卡徽标、因素表一致性行、分享卡。
25. **可信度档位/配色只有 `ENS_CONF_BANDS` 一个来源**（`_p4.js`，CSS 只读 `--cfb/--cfbg/--cfbd`）：`hi<18 / mid<35 / lo`，色 #178a52/#c07a10/#c0392b。一律 `ensConfOf(dv)`，**绝不再手写 18/35**。`dv==null` 返回**「中」**。文案用 `ensConfDetail`。
26. **分享卡必须复用页面文案与配色**（`conclOf(P)`/`gradeColor()`/`ENS_CONF_BANDS`）—— **卡片与页面说出两个不同结论是最糟失败模式**。纯 canvas 手绘、2× 像素密度（1560×800）、`toBlob`+`<a download>`；`toBlob` 缺失时静默不下载不报错。按钮初始 `disabled`，出结果后启用。
27. **`F_MAP_VARS` 10 个，不得删 `dew_point_2m`**：兜底 `Td=T−(100−RH)/5` 与真实露点差 0.3~1.2 ℃；删了会地图侧用近似、单点侧用真实 → 湿度项对不上。`max(1,10/10)=1.0` ⇒ 补上是**零成本**。
28. **三个内联 `<script>` 块共享全局作用域，`function` 声明是「静默覆盖」**：块 0 = `_p2.._p5b`，块 1 = `_TMapSecurityConfig`，块 2 = `_p6.js`（**后执行**，会悄悄顶掉块 0 同名函数；`const`/`let` 重复反而抛 SyntaxError 更安全）。**新增全局函数前先 `grep _p6.js`**；单点侧一律带 `ens` 前缀；由 `globals.js` 每次回归守着。
29. **两个缓存键族共用一道总闸门，但豁免策略相反**：`sweepPrefix(prefix,max,keepMine,protect)` 里**地图 `true` / 单点 `false`**。地图另有按日期 LRU（`MAP_DATA_MAX=3`）；**单点没有任何别的淘汰机制** —— 单条实测 **754,398 字符** ⇒ 同城 36 条 ≈ **27 MB**，故 `POINT_CACHE_MAX=4` 是**实测定的**。两族都必须 `FAMILY`（不含版本号）+ `PREFIX`（含版本号）成对定义，靠 `dropStalePrefixFamily()` 清上一版残留。单点缓存存**原始 API 响应**；键含**时段**，坐标取 0.1°（≈11 km，已在模式分辨率之下）。
30. **`TREND_DAYS` 必须经 `trendWindow(day0)` 夹紧**：`apiForecast` 用 `start_date`/`end_date`，**GFS 那一路没有 catch**（EC 有）；Open-Meteo 最远今天+15 而 `#date` 到 今天+10 → 区间越界 400 ⇒ **整轮趋势失败**。**天数只能来自 `TREND_DAYS` 一个来源**。
31. **地图代理地址只有一个占位符 `__TMAP_SERVICE_HOST__`**，`assemble.py` 注入（有环境变量 `TMAP_SERVICE_HOST` 用它，否则回落 `__WB_*`，**预览逐字不变**）。产物**不允许残留**，写盘前校验（判据只盯 `serviceHost: '<占位符>'` 那一行）。前端判"没配"一律走 `isMapProxyPlaceholder(host)`。**腾讯地图 key 永不进产物**，只在服务端 `TMAP_KEY`。
32. **图标必须内联**（单文件）：favicon 用 SVG data-URI，apple-touch-icon 用 **PNG**（iOS 不支持 SVG）。PNG 由 `assemble.py` 构建期用**纯 stdlib**（`zlib`+`struct`）生成，不依赖 Pillow。data-URI 里 `#` 必须写 `%23`。**刻意不做 `og:image`**（爬虫不取 `data:` URI）。
33. **色面掩膜（`cnMaskOn`）与排行榜口径必须一致 —— 图上没有的点不许上榜**：位图只有中国陆域 ⇒ 海域被一并裁掉，而 `cnMaskOn()` 在查询点境内无条件启用 ⇒ **沿海城市裁得最狠**（三亚 86%/上海 58%），`renderRank` 只按"有没有值"筛 ⇒ **"榜上有名、图上无影"**。修法＝**放宽掩膜（可分离定距膨胀，`MASK_KEEP_KM=300`）＋ `renderRank` 过 `mapVisibleAt()`**，**两者必须同批**。`mapVisibleAt` 读**色面栅格 alpha**（`f.img[...+3]>0`），不能读 `g.land[o]`；`renderRank(fld)` 由 `paintMap` 传**本次** `fld`。**不能用 ETOPO1 判海**。掩膜**不进缓存** ⇒ 不必升版本。
34. **色面边缘＝采样点凸包（`buildHull`）**，不再是"到最近采样点距离"（旧判据网格外走到 240 km 才归零 ⇒ 色面比采样区胖一圈、边界是 57 个圆盘并集）。凸包用局部等距投影（`kx=111.32·cos(olat)`、Y 用 `110.574`），`edges` 每 3 个一组 `(nx,ny,c)` 外法向归一化，包内 `nx·X+ny·Y+c ≤ 0`；**"包外多少公里" = `max over edges`（一个 max、无开方）**。包外只羽化 `FIELD_OUT_KM`（现 70 km）。**`FIELD_FULL=90` 现在是「距最近采样点的可信度分档阈值」，与色面边界是两个量**。
   **凸包到底几边形：去共线后几何是「正八边形」** —— 顶点 `(±4,±1)(±1,±4)`，内角 **135.0°**，长边 509 km / 短边 240 km 交替。**但 `hull.length` 会在 8 / 10 / 12 之间浮动，别硬编码**：长边上的网格点（如 `(3,2)`、`(2,3)`）与长边**严格共线**，单调链里 `cross <= 0` 弹不弹它们，只看经纬度往返的浮点噪声（实测同一份代码：大连/乌鲁木齐 8、三亚 10、其余 12）；何况 `ok[]` 还随**当前模型的数据可用性**变化。三者画出来是同一条八边形，只是"顶点"数不同。文档曾四处写"12 边形"、后来又改成"8 边形"—— **两种写法都不准确**。
   **别去"磨圆折角"**（第三轮方案批次 A，已判定不修并回退）：凸包尺度（500 km）远大于羽化带（70 km）⇒ 顶点方向能挪动的量只有 `70 × 0.082 ≈ 5.8 km ≈ 4 px`（实拍逐像素复核：最大通道差 10、alpha 最大差 0.069，占 0.05%/0.11%，代码已逐字节回退）；而 `max over edges` 是**切比雪夫型**距离（内角 135° 处只到真值的 `cos(22.5°)=0.924` 倍），换成精确欧氏距离也只挪这 4 px；改圆形色面又与"覆盖最外圈采样点"（圆 ≥495 km）和"120 km 可信半径"（圆 ≤440 km）**不可兼得**。
35. **分档填色（`N_BANDS=7`）后所有取色必须走 `bandColor(mode,v)`**：`bandOf(v)=clamp(floor(clamp(v,0,100)/100*N_BANDS),0,N_BANDS-1)`，取**档中点色** `rampColor(mode,(bandOf(v)+0.5)/N_BANDS*100)`。LUT 缩成 `Uint8Array(N_BANDS*3)`。图例色条用**硬停止渐变** `bandGradientCss()`。分档必须配 `FIELD_STEP=0.05`（0.1° 时屏上 4.6 px/格，档界锯齿）。**探针里"像素颜色↔数值单值映射"的断言必须改成"颜色↔档位"**。
36. **深色底图靠"同一 filter 套两层恰好抵消"**：`.mapwrap.dark #map{filter:invert(1) hue-rotate(180deg)}`，同一 filter 再套到全部叠加层（`.dimbase/.rlayer/.conflayer/.azilayer/.mlayer/.pinlayer`）—— `invert∘invert=id`、`hue-rotate(180)∘hue-rotate(180)=id`，两者仿射线性且与 alpha 合成可交换 ⇒ **色面像素一个都不变**。**绝不能加 `contrast`/`saturate`**（非对合）。
37. **相邻条带必须共用同一个"取整后"的边界像素**：`fitRaster()` 里给每条带加 0.75 px 去"盖亚像素缝隙"是**错的** —— 色面半透明，重叠行被 alpha 合成两遍 ⇒ 浅色底图上一条更深的横线。改法：先投影出所有条带上下沿，**统一取整到设备像素**（`Math.round(y*dpr)/dpr`），底沿直接取"下一条的顶"。审计：`SEAM=1 node _check/zoomprobe.js`，`gapCount` 必须 0 且边界逐位相接。
38. **不要重做「工具条死区」分析**：`.maptool select,.maptool input{min-width:118px}` 把 4 个 checkbox 撑到 118 px，但实测归零后 0 px / 0 行都不省 —— **纯属观感**。
39. **等值线必须独立成层，不许描进色面栅格**：色面像素 ↔ 数值的单值映射是 zoomprobe 像素级断言守护的性质（"看图反查数值"），在栅格上描线会打掉它。做法＝`.clayer`（z-index 2）逐条带栅格、与色面**同 per/count/尺寸**，`fitRaster` 里 overlay 用 `refit(arr, ownSize)`（纱与色面同尺寸 ⇒ 复制 transform；等值线是超采样 ⇒ 用同一个 `rect`、按**自己的**画布算 scale）。描线判据＝「4 邻格里任一档位不同就描」——注意是**两侧都描**（第十批实测：线横跨 1.46 格，不是 1 格）。`bnd<0`（无数据）与色面 alpha=0（被掩膜裁掉）的格都不描 ⇒ 线在掩膜边界与羽化尽头自然断开。**线 alpha 必须再乘色面 alpha**（否则外推区里"色面没了、线还浮着"）。审计：`mapaudit.js` I 段 —— **不透明像素（alpha≥200）必须全部落在 7 个档位色 ±2 内**（实测 22,199 个不透明像素、0 个越界）。
40. **等值线是屏幕空间矢量，线宽是屏幕常数**。拆成两件互相独立的事：**几何**只算一次（`buildContourGeometry`：marching squares 在**栅格坐标**下抽出档界折线，随值场重建）；**渲染**每帧做（`drawContours`：投影到**容器分辨率**画布，用固定的 `CONT_PX` 描边）。于是线宽与缩放、与栅格分辨率都无关。走到这一步之前试过两代"逐格栅格化"：一格宽的线（默认取景 1 格 ≈ 2.28 px ⇒ 是色带）、值场超采样 2 倍（1.64 px，**但放大后仍同比变粗**）—— 都不成立，用户为此连说两次"还粗"。**绝不能退回栅格化**。三个必须记住的点：① **插值必须在连续值场 `f.vals` 上做，不能在档位（整数）上做** —— 档位只有 7 个取值，任意相邻两格的"界"都在 0.5 处 ⇒ 交叉点**恒落在格边中点**，画出来是一条贴着格子走的折线（放大后满屏直角台阶）；要用 `CONT_LEVELS = (k+1)/N_BANDS×100` 这条与 `bandOf` 同源的尺子。② 投影必须复用色面那一次的 `rect`（`sx = rect.x + gx·rect.w/cols`、`sy = rect.ty + (gy − rect.r0)·rect.h/rect.h0`，`r0` 由 `buildStrips` 补上），否则线会与色面档界错位。③ 线的 alpha 按所在格的色面 alpha 分 **16 档**（同一档只 `stroke()` 一次）；四角任一格无数据（NaN）或色面 alpha 平均为 0 ⇒ 整格跳过（线在数据边缘与羽化尽头自然断开，不悬空）。**量线宽**要用「**墨迹覆盖面积 ÷ 折线总长**」，不能拿"一格像素有多大"当答案（前者与线方向无关）。覆盖面积 = Σalpha ÷「完全覆盖像素应有的 alpha」（`round(CONT_ALPHA×(档+0.5)/16)`）—— 用 `max(alpha)` 当归一标尺会被交叉处的 alpha 合成（156 压 156 → 216）抬高而把 1 px 量成 0.82 px。"色面全不透明"的阈值**取实测峰值 − 2**，不能写死 255：掩膜边缘被 `boxBlur` 抹过，色面 alpha 峰值只有 **230**。
41. **经纬网别去猜投影公式**：联调环境是等距圆柱、真机是墨卡托，两者纵向伸缩完全不同。只依赖 `projectToContainer` 的**单调性**（y 随纬度递减、x 随经度递增），对容器四边各二分一次求出可见经纬度，再对区间内整数度逐条精确投影 —— 两套投影下都成立，换 SDK 也不用改。1° 一档；线落**整像素中心**（`Math.round(y)+0.5`，否则 1px 线被浏览器糊成 2px 灰带）。它与「方位环」同一口径：`mapSet()` 为空时不显示。
42. **数据范围边界线（B1）必须按色面 alpha 逐段裁断** —— 这是与等值线**同一条纪律**（`buildContourGeometry` 里 `a4 < 1 → continue` 那句："色面这一格没上色 ⇒ 线不悬空"）。背景：色面在凸包内是**插值**、包外 70 km 是**外推并淡出**，但这条分界原本图上没有线；而低值区（档 0/1 的浅黄接近白，对浅底 WCAG 对比度只有 **1.05**）几乎与浅色底图同色 ⇒ "这片到底算过没有"读不出来。试过改色阶（抬深锚点只到 1.14、7→5 档只到 1.22）—— **无效**，所以改成把范围本身画出来。画在**凸包本身**（那里 alpha = 1）而不是羽化带外缘；样式与等值线**同色系但更淡、且用虚线**（`CONT_RGB`、alpha 0.42、`setLineDash([5,4])`、固定 1 px），同一屏要能分清"档界"（实线）与"范围"（虚线）。
   **必须裁断**：海陆掩膜会成片删掉色面（沿海城市的凸包大半伸进海里，三亚实测 20 个顶点/边中点里 5 个落在无色区），照几何原样连成整圈就会有一段**浮在没上色的海面上** —— 那正是"一撮浮在空处的线"。做法＝沿每条边采样、只画色面真有像素的弧段；采样在**容器像素**里做（与等值线同一套 `rect`；注意 `rect[i].h0` 只是**本条带**的行数，要加 `r0` 才回到全栅格行号），步长 **1 px**（再大就可能多画出去一格），**每条弧段单独 `beginPath()`+`stroke()`**（同一路径反复 stroke 会让 alpha 叠加变深）。
   它与等值线**共用一块画布**（`.clayer`），所以 `mapaudit.js` 里那条"等值线墨迹不悬空"断言**同时就是 B1 的端到端证明** —— 实现前不裁断时那条断言立刻报 `悬空 81 处`，裁断后归 0。另加两条结构性断言（`edgePts === hullN`、`edgeIn > 0`），**顶点数不硬编码**（见 34）。`MapMod.edgePts` / `edgeIn` 供探针读。
43. **`MapMod.gratOn` 必须拆成「用户偏好」与「图面可用」两件事** —— 经纬网开关（批次 C1）落地时的坑：`gratOn` 原来**兼两职** ——① `drawGraticule()` 派生的"网已经画出来了没"，② `gridOn()` 读它决定 `.clayer` 的显隐。而 `drawGraticule` 里那句 `if (!MapMod.gratOn) { MapMod.gratOn = true; refreshGrid(); }` 会在**每次 `fitRaster`**（被 `tilesloaded` 反复触发）时**静默把用户的选择打开**。拆法：`gratUser`（纯偏好，初值 `true`）与 `gratOn = gratUser && mapSet()`（图面可用）；拆开之后 **`gridOn()` 一行都不用改**。
   **关掉经纬网时不能只靠 `.clayer` 的 `.on`** —— `.on` 的语义是"等值线或经纬网**有其一**即显示"，关掉网时等值线还在、`.on` 仍为真 ⇒ 必须显式 `MapMod.gridSvg.style.display = "none"`；反过来"关→开"若视野没动，会被 `gratSig` 签名闸门直接 `return`、`display` 永远停在 `none` ⇒ **`setGratUser()` 必须让 `gratSig` 失效**（`MapMod.gratSig = ""`）再调 `drawGraticule()`。`setGratUser(on)` 是这个开关的**唯一入口**。
   **图层开关一律不持久化** —— 既有 4 个开关（色面/等值线+经纬网/可信度/深色底图）都不存 localStorage，项目里**没有通用的偏好存储机制**，新开关照样不存（C1 偏离原方案"持久化"之处，是有意的）。审计：`mapaudit.js` J 段三条（开关存在且默认开 / 关掉后 `display="none"` 且 `contN>0` 不受影响 / 开回来 `display!=="none"`）。

44. **窄屏（≤760px）有两条专属路径，断点宽度写在三个地方** —— `tpl/template.html` 的两条 `@media (max-width:760px)`（顶部条、提示卡 dock）与 `_p6.js` 的 `TIP_DOCK_MQ`。JS 侧收口在 `tipDock()`（用 `matchMedia`，不用 `innerWidth`：判的是"屏幕窄"而非"容器窄"，桌面拖窄侧栏时卡片仍应跟随指针）。三处宽度必须一致，否则会出现"JS 以为该贴底、CSS 却仍在居中定位"或反过来。
   **① 顶部条**：`flex-wrap:wrap` + 中间文字列没有 `min-width:0` ⇒ 窄屏摊成 3 行（实测 175 px / 20.8%）。压法按信息价值排序：sub（技术栈罗列，纯装饰）隐藏 · h1 压到 **14px** · badge 与标题同行 · logo 34→26 · **sticky 改 static**。最后一条是实拍才发现的第二层问题：压薄后的 43 px 虽然小，半透明**浮在内容上**，实拍里正好压在"① 查询条件"的城市按钮行上、把那行截断成两半；而顶部条带的信息（地名/日期/时段）在地图卡片与结论卡里都有 ⇒ 手机上它的边际价值为负。**h1 定 14px 而非 15px**：15px 在 360px 屏上会折成两行且**断在词中间**（"概/率与观赏质量"），断行难看比小一号字更伤。结果 43 px / 4.4% / 1 行，360×640 下同样成立。
   改成 `flex-wrap:nowrap` 后标题列自己成了新雷：**标题列 `<div class="top-tx">` 必须 `min-width:0`**（第三批真机反馈）—— h1 是 `white-space:nowrap`，其 min-content = 整行标题宽，flex 子项默认 `min-width:auto` ⇒ 标题列**不许收缩**，把 `flex:0 0 auto` 的 badge 顶出容器右缘 61 px（390 视口下 badge 右边界 451 = `body.scrollWidth` 的唯一来源），真机据此可横向拖出一整条空白。**只写 `min-width:0`，别写 `flex:1`** —— 那会跟 `.spacer` 分剩余空间，badge 不再贴右。代价：窄屏标题被 h1 的 ellipsis 截成「霞光预报 · 朝霞 / 晚霞 概…」—— badge（地名/日期/时段）才是真正被反复看的那一行，取舍成立。
   **② 提示卡走 `.tip.dock`（贴底通栏）**：跟随指针定位在 ~340 px 宽的容器里必然溢出 —— 卡片内容撑到 260 px+，再加 `translateX(-50%)` 居中，`.mapwrap{overflow:hidden}` 两侧裁掉（改前实测指针 y=60 时下方被裁 23 px）。dock 后 `left/right/bottom` 由 CSS 决定、`max-height:72%` + `overflow-y:auto` + **`pointer-events:auto`**（否则在窄屏既滚不动也点不着）。**dock 时 JS 必须显式清掉 `left/top/--tipshift` 与 `below`** —— 它们是宽屏路径留下的行内样式，而**行内样式优先级高于 CSS 规则**，不清就会把贴底卡片拽回"跟随指针"的老位置。
   `.dock` 背景要**不透明**：`.tip` 的 `rgba(255,255,255,.98)` 是为桌面那把 220×172 小卡片设计的，2% 透明在那点面积上看不出来；而贴底通栏有 326×302、底下正压着图钉（`.pinlayer` z=6）与数值直标（`.mlayer` z=5），那 2% 会让它们整片透上来变脏点。层序本身是对的，问题纯在 alpha（像素级复核：改后卡片内空白区非白像素 **0** 个）。
   **dock 卡片的 `z-index` 是 2000 而不是 20** —— 腾讯地图 SDK 会在**触屏真机**上自动加缩放（+/−）与罗盘控件，z-index 是 SDK 内部值、无从约定；真机实测它们整只压在 z=20 的卡片上，连卡片右上角的 × 都被盖住（第二批真机反馈）。**headless 探针里 SDK 根本不渲染这些控件**（`#map` 一层只有自绘层：canvas + dimbase/rlayer/clayer/conflayer/mlayer/pinlayer/azilayer）⇒ 这个问题**量不出来、只能防**：给远高于 SDK 常见取值（≤1000）的防御值，探针断的是 `z ≥ 1000`（防回退）加 `elementFromPoint` 命中 × 自身（将来有任何层压上来会先红）。卡片盖住控件是 bottom sheet 的预期行为 —— 要操作地图先关卡片，三条关闭路径就是给这个用的。桌面端 `.tip` 保持 z=20 不动。
   **触屏没有 `mouseleave`** —— 卡片一旦被点击钉住就再无自动收起机会，这就是"按不掉"的根因。关闭路径给三条：卡片自带 **×**（`@media (hover:none)` 才显示，桌面上 pointer 能穿过卡片触发 mouseleave，不需要它）· **再点一次同一处**收起（`MapMod.pinLL` 判重，触屏通用手势）· **点 `.mapwrap` 以外**收起（document 捕获监听）。后者**必须事件时**才判 `tipDock()`：在 `initMap` 里求值的话，窗口跨过断点（平板转竖屏、手机横竖屏、桌面拖窄）后就与"再点一次"一起失配。同理，跨断点时若卡片正开着，要重排一次（`TIP_DOCK_MQ.addEventListener("change")`，静默 hide→show，别让用户看到卡片凭空消失又出现）。
   **④ 拖动地图 ⇒ 收起贴底卡片**（第四批真机反馈"**部分时候**无法滑动地图"）：`.tip.dock` 是 326×302 的通栏（`pointer-events:auto`，卡片要能滚能点），窄屏地图只有 420 px 高 —— **卡片开着时下半区起手的一切触摸都被卡片吃掉**，"部分时候滑不动" = 卡片开着的时候，bottom sheet 固有冲突。出口走惯例（Google Maps 同款：一拖卡片就走）：document 捕获层 `touchstart` 记起点（`target.closest("#tip")` 判起手是否在卡片内）、`touchmove` 位移 >**12 px** 即 `hideMapTip()`。三个必须：**用 touchmove 位移判定而非 pointerdown**（pointerdown 无法区分点击与拖动，在那里收卡会先藏卡清掉 `pinLL`，click 到来时"再点同一处收起"失效、同一处重新弹卡）；起手在卡片内不收（那是滚卡片）；`passive + capture`、绝不 `preventDefault`（只读不拦截，地图手势仍由 SDK 全权处理）。至此关闭路径共**四条**。
   **⑤ `#map` 必须 `touch-action:none`**（第三批真机反馈"地图无法左右滑"的另一半根因）：页面一旦有横向溢出，浏览器的横向平移手势会跟地图拖动**竞争**（真机单指横滑被浏览器抢走）；`touch-action:none` 把 `#map` 内全部手势判定交给腾讯地图 SDK。**绝不能设在 `.mapwrap`** —— `.tip.dock` 是它的后代且要纵向滚动（`overflow-y:auto`），手势判定取触摸链上所有元素 touch-action 的**交集**，祖先 none 会连卡片内滚动一起禁掉。
45. **「藏提示卡」统一走 `hideMapTip()`** —— 此前散在 7 处、每处只做 `tip.classList.remove("on")`。加上 `pinLL` 之后，只藏卡片会留下**三个**不一致状态：① `pinLL` 仍记着上一次钉住的位置，换地点后在新位置点一下若恰好与旧值相同，就被误判成"再点一次"而直接收起；② 待处理的那一帧悬停没取消（`mouseleave` 上踩过），卡片藏了又被弹回来；③ **`.dock` class 残留 —— 最严重，真机症状级（第五批真机反馈的根因）**：窄屏媒体查询里 `.tip.dock` 带 `pointer-events:auto`（卡片要能滚能点）+ `z-index:2000`，而 `.tip` 基础态是 `pointer-events:none` + `opacity:0`；只 `remove("on")` 的话卡片只是"看不见"，那块 **326×302 的隐形热区仍扣在地图下半部** —— 真机表现：点开过一次卡片再关掉之后，① 地图单指拖不动（触摸全被透明卡片吃掉）；② 双指落在这块上时它的 `touch-action` 是 `auto` ⇒ **触发浏览器整页 pinch-zoom**（落在真地图上则被 `#map` 的 `none` 拦住 ⇒ 表现为"有概率"）。前两轮把它误判成"卡片开着时挡住屏幕"，所以"关掉卡片就正常"这个反直觉现象一直没被解释。
   `hideMapTip()` 三件事一起做：`remove("on")` + **`remove("dock")`** + `MapMod.pinLL = null` + `MapMod.cancelHover()`。**`cancelHover` 必须挂到 `MapMod` 上**：`showMapTip` 是全局函数、拿不到 `initMap` 里的局部函数。**判据取端到端**（探针已断）：关闭后 `document.elementFromPoint(卡片打开时的中心点)` 必须落回 `#map` 之内，而不是命中隐形的 `#tip`。另：卡片可见时 `.tip.dock` 加 `touch-action:pan-y`（放行它需要的纵向滚动、禁掉 pinch-zoom，防整页缩放）。`showMapTip` 内部那两处早退（`!isNum(v)`、`mind > TIP_RANGE_KM`）**不走**它 —— 那是**被数据否掉**而不是用户主动收起，且 `pinLL` 还没被写过。
46. **`overflow-x:auto` 的滚动容器必须显式 `min-width:0`** —— `overflow-x:auto` 本身**不**封顶：作为 flex/grid 子项时它带着 `min-width:auto`，会被内容（本例是 `table#fac.ftab`，`white-space:nowrap` 表头）一起撑开。手机上这不是"某个表格有点宽"，而是把整页 `scrollWidth` 从 390 顶到 451，移动端浏览器据此**放大布局视口**，效果是**整页被缩小**：字变小、留白变大、每屏能看的信息都变少。`.t-scroll` 加 `min-width:0;max-width:100%` 后，表格老老实实在自己容器里横向滚动（client 340 / scroll 445）。
   **配套的量测纪律一：判"越界"，不要判"是否最宽"。** 第一版 `mobileprobe` 报"最宽元素 = `table#fac.ftab`（right 470）"，差点归咎于它 —— 但它被 `.t-scroll` 正确兜住了，横向滚动正常。横向滚动/裁剪容器内的元素要一并排除（`.t-scroll`、`.mapwrap`）。
   **配套的量测纪律二（第三批真机反馈的教训，最重要）：参照必须用 `documentElement.clientWidth`，绝不能用 `innerWidth`。** 元素越界 → `body.scrollWidth` 增大 → Chrome 移动模拟把布局视口**等比放大**（390 设定实测拿到 `innerWidth 451`，×1.157）⇒ 用 innerWidth 当参照的"越界"断言**永远抓不到自己制造的溢出**（自指掩盖）—— 上一轮照旧口径全绿、真机却仍能横拖出空白，把参照换成 `clientWidth`（390）后立刻抓到 `#topBadge 305..451`。探针 F 段同时断 `html.scrollWidth ≤ doc.clientWidth+1`（页面不可横向拖）与 `#map touch-action=none` / `.mapwrap≠none`。

52. **404 页是第二个产物 `404.html`**（2026-10-12 新增）—— 本项目是纯静态单文件站，**没有前端路由**，所以"访问不存在的路由"只能靠托管平台那条约定：路径匹配不到任何文件时取站点根下的 `404.html` 并以 **404 状态**返回（Cloudflare Pages / GitHub Pages / Netlify 同一条）⇒ **不需要任何 rewrite 配置**，也不需要 `_redirects`。
  ① **页内地址必须是站点根的绝对形式**：404 页是在**请求的那个 URL** 下被返回的，写相对 `index.html` 会按 `/a/b` 解析成 `/a/index.html` —— 越深的错链错得越离谱；写死 `/` 又照顾不到子路径部署（GH Pages 项目页是 `/仓库名/`）⇒ 与地图代理同思路走**构建期注入** `__SITE_BASE__`（默认 `/`，缺首尾斜杠由脚本补），**占位符不允许残留**（残留即 `return 1`，因为这种错只在部署后才看得见）。
  ② **必须自包含、零外部引用**：它会被各种奇怪客户端打开（爬虫、禁了 JS 的浏览器），一套外部字体/图标加载不到就变白板；图标与主页同枚、一律内联。

  ④ **路径显示用 `textContent`**（路径是用户可控输入，拼 `innerHTML` 就是反射型 XSS），长路径要 `word-break:break-all`（否则窄屏把卡片撑破、把 `scrollWidth` 顶出去，见 46）。

## 54 · 离线 / PWA（F1）：可选产物，默认仍是单文件
**PWA 与"单文件产物"正面冲突**：SW 的注册脚本必须是**同源 http(s) 的真实 URL**（`blob:` / `data:` 一律被拒），所以单文件 PWA 物理上做不到。取舍：`PWA=1` 才多产 `manifest.json` / `sw.js` / `icon-192.png` / `icon-512.png`；**默认构建仍只有 index.html 与 404.html**。`pwaprobe` 的 A 组专门守这一条（无 manifest 链接 / 无占位符残留 / 脚本块数仍 4 / 产物目录只有 2 个文件）—— 只测 PWA 那一半等于悄悄把自包含约束丢掉。
- **SW 绝不缓存气象响应**：过期预报比没有预报更危险（用户在山顶拿昨天的数据当今天的看）。只认一份**预缓存名单**（`./` `index.html` `404.html` `manifest.json` 两张图标），stale-while-revalidate；跨域（气象 / 地图 SDK 与瓦片 / 省界 GeoJSON）与**同源的地图代理 `/_TMapService`** 一律不拦截。实测：气象请求 9 次，缓存里气象条目 0 条。
- **缓存名 = 产物内容的 sha256 前 12 位**（`build_id`，由 `assemble.py` 注入），不是手写版本号常量 —— 内容一变名字就变，旧缓存在 activate 时清掉。
- **注册不得新增内联 `<script>` 块**（块数 4 是 syntax.py / globals.js / assemble.py 共同守着的不变量）：`initPWA()` 从 `link[rel="manifest"]` 的 href 推出 `sw.js` 地址与 scope ⇒ manifest 存在即 PWA 版，子路径部署自动成立，不需要再注入地址常量。
- 注册是"增强"：没有 SW / 注册失败 / `file://` 打开，一律静默跳过。离线提示条 `#netBar` 放在 `.top` **外面**（顶栏"窄屏必须一行"是约束 44）。取数失败给**离线专属**文案，不是"稍候 1 分钟重试"（约束 11 的延伸）。
- `assemble.py` 的 `OUT_DIR` 让探针把另一套构建产到别处，不覆盖仓库产物；`wr()` 认绝对路径。

## 55 · 本地校准（F4）：只展示、只存本机、不够样本不给结论
**风险是"校准被误当成模型输出"** —— 用户看到"实际 50%、偏差 −37"会以为模型被改过了。故四条边界一起成立才算落地：
- **不回改模型**：校准块（`#calibHead` / `#calibStat`）与结论卡各写各的 DOM，**永不互相写**；`calibprobe` 用"标注前后模型指纹逐字段相同"（概率文本 + 大数 + 徽章 + 环 `stroke-dashoffset` + 每个 `#models .mnum` + `#fac tbody tr` 行数，**136 字符**）把这条断死。文案主语永远是"模型"（"模型在 {lo}–{hi}% 这一档平均报 {pred}%"）。
- **不够样本不给结论**：累计 `CALIB_MIN_N = 8` 次 **且** 当前分桶 `CALIB_MIN_BUCKET = 3` 次才出数字，之前只显示进度行。分桶按预测 P 每 `CALIB_BUCKET = 20` 个百分点一档；同地区判定 `CALIB_GRID_DEG = 0.5`°（`Math.round(lat/0.5)`,`Math.round(lon/0.5)` 同格）；"实际出现" = 标注 ≥「一般，能看」（`CALIB_HIT_MIN = 2`）；存储上限 `CALIB_MAX = 200` 条。
- **"没看到" ≠ "没有霞"**：`a = -1`（无法判断）**不进统计**（分子分母都不进），否则"没出门看"会被算成预报失败，把校准**系统性拉低**。
- **关掉 ≠ 删除**：`#calibOff` 只影响入口与展示，已存标注**一条都不删**；清空是另一个按钮 + 二次确认。两件事刻意分开，防止"想安静一下"顺手毁掉几十条样本。
- 另两条：**未来时段不给标注**（入口只看既有的 `leadH`，不新增阈值）；**快照模式不出现**（`snap=` 是别人发来的，不该让接收者往自己机器写数据）—— 模板上靠 `data-snaphide` 兜底，`renderCalibBox()` 也有一层。
- 存储 `sunsetbot.calib.v1`（先读 → 白名单 → 合并 → 写；坏行静默降级，不抛错、无迁移代码）；`calibOff` 属偏好键 `sunsetbot.pref.v1` 的**布尔白名单**项。
- 六个阈值常量留在源码顶层并被 `docfacts` 机读核对（手抄错了等于文档在教人用一套实际不生效的阈值）。
- **别按"元素总数"断"哪几张卡收起"**：`snapprobe` 原按 `[data-snaphide]` 总数 `=== 4`，F4 的校准块也是 `data-snaphide`（却是结论卡的子块、不是一张卡）⇒ 首跑真失败。改成按 `div.card[data-snaphide]` 的**身份**数（恰 4 张）**且**所有 `data-snaphide` 块都收起。

## 方法论
**对有意的语义变更做回归时，不能拿改造前的实现当基准**。必须写**结构完全独立、语义相同**的第三方参考实现（不复用被测实现任何中间字段），再做双重差分：① 第三方(旧语义) vs 旧实现 → 0 ⇒ 尺子可信；② 新实现 vs 第三方(新语义) → 0 ⇒ 新实现正确。`zoomprobe.js` 的 `refThird` 即此模式；`calibprobe.js`（F4）也用同一模式复刻了分桶/归组/统计。

### 判据的病（已踩 5 类，都是"绿灯但没测到该测的东西"）
1. **文本扫描不剥注释** ⇒ 判据恒真（`darkprobe` / `pwaprobe`，3 次）。
2. **按"元素总数"断死** ⇒ 新增同类元素就变成改数字式的假失败。按**身份/集合**断（F4 后 `snapprobe` 改成 `div.card[data-snaphide]` 恰 4 张 + 所有同类块都收起）。
3. **固定 `sleep` 等异步** ⇒ 慢机器上假绿、快机器上白等。
4. **判"页面就绪"用了词法全局** ⇒ `window.State` 恒 `undefined`，轮询跑满预算、`calibprobe` 零输出被杀两次。要用 `typeof State !== 'undefined'`；重复导航要"导航标记"握手且超时抛错。
5. **计数器/累积量在最后统一取值** ⇒ 中间其它动作被一起算进来，名字说测 A 实际测 A+B。`404probe` 的 `extHits` 就是这么一回事：桌面段清零后，B 组为了测"返回上一页"载入了两次**首页**，首页的气象请求被掐断并计进同一计数器 ⇒ "404 页零外部请求"实际测的是"404 页 + 首页"，靠时序侥幸通过。**修法：在被测动作结束那一刻取值**，并记下被拦的**地址**供诊断。
