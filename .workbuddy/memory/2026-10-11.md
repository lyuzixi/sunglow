## 第八批（勘察）：色面"看起来像一团雾"的量化诊断

用户反馈"地图看上去怪怪的"，要 莉景天气（深色 App 风、离散色斑）与 sunsetbot
（等值线 + 分级填色 + 经纬网）那种效果。先量测再动。

新增探针 `_check/styleprobe.js`（不进 all.py 序列，与 `pointcache.js` 同级；
用**只随位置缓慢变化**的合成数据，模拟"只有局部有信号"的真实分布）。

实测（广州，栅格 143×131 ＝ 1464×1449 km）：

| 指标 | 实测 | 含义 |
| --- | --- | --- |
| 地图像素 / 栅格格 | **4.56** | 一格格子 ≈ 4.6 屏幕像素 |
| 上色格占比 | 72.8% | |
| **完全不透明(alpha=209) 占比** | **28.9%** | 七成色面是半透明的 → 发虚 |
| 到最近采样点距离 | P10 **29** · P50 **69** · P90 **204** · max 240 km | 中位像素离最近采样点已 69 km |
| 淡出带宽（屏幕） | **≈180 px** | 一圈大雾 |
| 色面内不同 RGB 数 | 168 | 连续无级、没有一条边界 |
| 数值分布 P25/P50/P75 | **44.7 / 48.4 / 54.1** | 中间 50% 的格子只跨 **9.4 分** |
| 可信度纱覆盖 | 已上色面积的 **46.2%** | 勾上像渲染错误 |

**五条根因**（按影响排序）：
1. **取景比采样区大一圈**：采样网格直径只有 ~1000 km，栅格却 1464 km —— 多出来的每个方向
   约 240 km 全是"外推 + 淡出"区。色面边界是 57 个半径 240 km 圆盘的并集 ⇒ 扇形缺口。
2. **数值被插值压扁**：57 个点的值域被 IDW 抹平，色阶却按**点**的值域拉伸 ⇒ 大部分区域
   落在一个很窄的色段里，看上去"一个颜色"。
3. **可信度纱是整片实心灰**（`rgba(100,116,139,.44)`），覆盖已上色面积的 46.2%。
4. **色阶低端是白色**，与浅色底图分不开 —— 这才是"底图压暗"这个补丁存在的原因。
5. 次要：`FIELD_BLUR=8 格(88 km) > FIELD_FULL=75 km(6.8 格)` ⇒ 模糊核比实心半径还大，
   采样区内部平均只有 206.5/209（98.8%），不发虚但不干净。

**参照物在做同一件事**：把**连续场变成有边界的东西** —— sunsetbot 用等值线 + 分级填色，
莉景用离散色斑 + 深色底。我们目前是"连续渐变 + 白色低端"，所以只能看成雾。

**改法会撞到的既有约束**（必须一起处理）：
- 分级填色会让 `zoomprobe.js` 的"**像素颜色 ↔ 数值单值映射**"断言失效（硬约束 20），
  要同步改成"颜色 ↔ 档位"；`cdp.js` 里读色面 alpha 的纱断言不受影响。
- 收紧 `FIELD_RANGE` 会同时收紧 `MAP_IDW_MAX` 与 `TIP_RANGE_KM`（硬约束 16 的单一来源），
  悬停可取值范围会跟着缩 —— 这是**有意的**，不是遗漏。
- 色面渲染**不进缓存**（`mapCachePut` 只存 `{ts,obj}` 数据），所以改渲染参数**不需要**
  升 `MAP_CACHE_PREFIX`；但只要动了 `FIELD_STEP`/`FIELD_BLUR` 这类几何参数就要重新评估（硬约束 1/4）。

### 四、顺手抓到并修掉的一个真缺陷：条带接缝

`fitRaster()` 原先给每条带加 **0.75 px** 高度去盖亚像素缝隙（注释写着"后画的条带在上，无副作用"）。
**这个"无副作用"是错的**：色面是半透明的，重叠那一行会被 alpha 合成两遍 ⇒ 浅色底图上一条更深的横线。
旧配色（28.9% 不透明 + 88 km 大模糊）把它摊没了；换成凸包 + 分档后不透明占 50.6%，它就显形了。
实测：`style-after.png` 第 511 行亮度比邻行低 **7.7**（整图只有这一条异常行）。
修法：先投影出所有条带的上下沿，**统一取整到设备像素**（`round(y*dpr)/dpr`），
底沿直接取"下一条的顶" ⇒ 缝隙与重叠同时消失，不需要任何补丁。
修后：`SEAM=1` 审计 `{"n":3,"gapCount":0,"worstGap":0,"head":["0:643.3~826.3","1:826.3~1008.3","2:1008.3~1099.3"]}`
（边界逐位相接），全图横向异常行 **0 条**。

## 第一轮：值场超采样（`CONT_SUPER=2`）—— 有效，但治不了根

先量化："粗"不是描边参数，而是**判边格子有多大**。`FIELD_STEP=0.05°` 在默认取景下

（顺带勘误第九批文档那句"只描一侧 ⇒ 线宽恒 1 格"—— 与代码不符。）

## 第二轮：屏幕空间矢量描边（最终）

拆成两件互相独立的事：**几何**只算一次（marching squares 在栅格坐标下抽档界折线），
**渲染**每帧做（投影到容器分辨率画布、按固定 `CONT_PX=1` 描边）⇒ 线宽是屏幕常数。

**踩到的第二个坑（比线宽更隐蔽）**：第一版矢量实现拿 `f.band`（整数 0..6）当标量场
抽 `level=k+0.5`，结果 `(t-v0)/(v1-v0)` 恒等于 ±0.5 ⇒ **交叉点永远落在格边中点** ⇒
画出来是"贴着格子走的折线"，放大后满屏直角台阶。
改成在**连续值场 `f.vals`** 上找档界对应的值（`CONT_LEVELS=(k+1)/N_BANDS×100`，
与 `bandOf` 同源）之后才变成光滑曲线。**这条是必须记住的：插值要在值场上做。**

投影复用色面那一次的 `rect`（`sx=rect.x+gx·w/cols`、`sy=rect.ty+(gy−r0)·h/h0`），
为此给 `buildStrips` 补了 `s.r0`（该带在栅格里的起始行）。

## 探针：I 段整段重写（仍 8 条，总数仍 20）

- **画布＝容器分辨率**（`cv.width===round(host.clientWidth×dpr)`）—— "线宽与缩放解耦"的前提。
- **墨迹不悬空** —— 探针自己重建投影（读 DOM 的 `getBoundingClientRect`，不读实现里的 rect）。
- **可见宽 = 墨迹覆盖面积 ÷ 折线总长**。量了**四次**才对，四个坑：
  1. `Σalpha/255 ÷ 总长` → 0.60 px。总长含**画布外**的段（墨迹被裁、长度照算）；
     且 `alpha/255` 量的是**墨色浓度**（线本身 α≈0.67）不是几何覆盖率。
  2. 只在"色面全不透明区"量 + 用 `max(alpha)` 归一 → 0.82 px。不同档位的线
     在交叉处 **alpha 合成**（156 压 156 → 216），几个交叉点就把标尺抬高。
  3. 改用直方图峰 → 测不出。`dpr=1` 下斜线大多数像素只被**部分**覆盖，分布弥散没有峰。
  4. **`Σalpha ÷ (round(CONT_ALPHA×(档+0.5)/16)) ÷ 折线总长` → 1.07 px** ✓
     还原的是**几何面积**：改 `CONT_ALPHA` 不会让宽度读数变，改线宽才会。
- "色面全不透明"的阈值**取实测峰值 − 2，不能写死 255**：掩膜边缘被 `boxBlur` 抹过，
  色面 alpha 峰值只有 **230**。

## 手机端适配（真机反馈，已落地）

用户真机截图两个问题：**① 顶部信息条占屏过大**；**② 手机端点地图弹出白色卡片、
按不掉、且信息被遮**。

### 问题 ① 顶部区

**根因**：`.top-in` 是 `flex-wrap:wrap`，中间的文字列没有 `min-width:0`，
于是 `h1` 与 `sub` 先各自撑成整行、`badge` 再被挤到第三行；`.top` 又是 sticky。
390×844 实测 **175 px（20.8%）／摊成 3 行**。

**压法按信息价值**：sub 隐藏（技术栈罗列，装饰）· h1 14px · badge 与标题同行 ·
logo 34→26 · **sticky 改 static**（最后这条是实拍才发现的第二层问题：
压薄后的 43 px 虽然小，半透明浮在内容上，实拍里正好压在"① 查询条件"的
城市按钮行上、把那行截断成两半；而顶部条带的信息在地图卡片与结论卡里都有）。
⇒ **43 px（4.4%）／1 行**，360×640 下 43 px 同样成立。

h1 定 14px 而不是 15px：15px 时会折成两行且**断在词中间**（"概/率与观赏质量"），
断行难看比小一号字更伤。

### 问题 ② 提示卡

**根因三条**（都不在桌面出现，所以 mapaudit 量不到）：
1. **遮挡**：跟随指针定位在~340 px 宽的容器里必然左右溢出（卡片内容撑到 260 px+，
   再加 `translateX(-50%)` 居中），`.mapwrap{overflow:hidden}` 两侧裁掉。
   实测改前指针 y=60 时**下边被裁 23 px**。
2. **按不掉**：触屏没有 `mouseleave`，卡片被点击钉住后没有任何自动收起路径。
3. **行难看**：172 px 窄卡里每行都难折（"晚霞/方位"、"云底/云/边界"）。

**落地**：
- 新增 `.tip.dock`（`@media max-width:760px`）＝ **贴底通栏**，不再跟随指针。
  JS 侧对应 `tipDock()`，**dock 时必须显式清掉 `left/top/--tipshift` 与 `below`**
  ——行内样式优先级高于 CSS，不清会把贴底卡片拽回老位置。
  `max-height:72%` + `overflow-y:auto` + `pointer-events:auto`（不然滚不动、点不着）。
- `.dock` 背景改**不透明**：`.tip` 那个 `rgba(255,255,255,.98)` 是为桌面小卡片设计的，
  220×172 上 2% 透明看不出来；326×302 压着图钉与数值直标时会整片透上来（像素级复核：
  改后卡片内空白区非白像素 0 个）。

### 五追 · 关闭卡片后地图滑不动 + 双指触发整页缩放（第五批真机反馈，真根因）
