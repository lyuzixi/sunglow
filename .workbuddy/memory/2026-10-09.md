### ① 模型分歧着色维度（第 4 个着色依据）

`divergeOf(o)` = gfs/ec/rt 三套 `mixedIndex(P,Q)` 的极差。
**它不花任何额度** —— 每点的 `p`/`q` 里本来就同时存着三套结果，`ens` 只是它们的
加权几何平均。着色维度加 `<option value="dv">`。

两个关键设计（都是"为了不误导"）：
- **<2 套模型有值时返回 `null` 而不是 0**。返回 0 会在 EC 缺失那天把"少了一套模型"
  伪装成"三模型高度一致"。空态文案也换了口径。
- **`dimOf` 里必须在取 `mk` 之前分流**，否则切模型会让这张图莫名其妙地变；
  同时 `#mapModel` 置灰。连带改：地图标签、排行榜标题/口径、下钻口径、悬停卡
  （首行"模型分歧 ΔI"、模型行改"参与模型 GFS / ECMWF / 光追"，并并列三模型 I 值）。

### ② 查询点图钉 + 采样点显隐

`MAP_KEEP_KM` 允许值场中心与查询点相差 ≤120 km 却**没有任何视觉提示**；
57 个采样点此前也完全不可见。新增 `.pinlayer#mapPins`（纯 DOM，projectToContainer）：
查询点常显、值场中心只在相距 >5 km 时画、采样点受 `#showPts` 控制。
`renderPins()` 按签名（勾选+点数+值场中心+查询点）决定是否重建 DOM ⇒ **拖动只改
transform、一个节点都不重建**（实测节点对象复用成立）。

### ③ 可信度纱

距最近采样点 > `FIELD_FULL` 的格子铺一层中性灰纱（＝色面开始淡出的那一圈）。
**独立画布 `.conflayer`，绝不动色面像素** —— `sampleRaster`/`zoomprobe` 读的是
`MapMod.strips`；断言直接钉住"开启纱前后色面指纹必须完全相同"。
距离场 `f.dkm = √aMin × 6371.0088` 挂在几何上（`evalField` 本来就算了同一个量）。
实测覆盖 **5,649 / 20,305 格 = 27.8%**，与「色面有像素 ∧ dkm > FIELD_FULL」的
格子数**逐一相等**。
顺手修 `ensConfOf`：过期注释（"700 km 半径外推"）、分档 150/300 → `FIELD_FULL` /
`FIELD_RANGE÷2`、"该城市自身" → "该采样点自身"。

### ④ 底图压暗

色阶低值端是白色、底图也是浅色 ⇒ 分不开。加 `.dimbase`（夹在底图与色面之间，
`opacity .45`，**默认关**）。**不用腾讯地图自定义样式**：样式 ID 在联调环境
（preview.html 的 mock）根本发不出请求，改了无法验证。
**顺带把图层 z-index 归位**：0 底图压暗 / 1 色面 / 2 纱 / 3 数值直标 / 4 图钉 /

"加载中"遮罩压在色面之上却被直标压住，是个说不过去的次序。

### ⑤ 已缓存日期回放标记

`#mapDateSel` 的 18 个选项此前长得一样，用户不知道切哪个是免费的。
加两级标记：**已就绪**（内存）/ **已缓存**（localStorage）。只写 `textContent`，
`value` 不动；`（今天）/（明天）`基础文案存进 `option.dataset.base`（只一处定义）。

## 那行被删掉的重复调用是个真 bug 苗子

原代码是：

```js
setLocation(State.lat, State.lon, State.name || "我的位置", State.region || "");
if (!hasUrl) setLocation(State.lat, State.lon, "上海市", "上海市");
```

第一行已经是"按 `State` 定位"，第二行又在没有地址栏参数时把它**覆盖成写死的上海**。
改默认城市时若只改 `State` 不改它，首屏就会出现**标题写着"上海市"、数据其实是广州**
的自相矛盾（坐标来自第一行，名字来自第二行）。删掉第二行后，
**默认城市全应用只剩 `State` 这一处定义**，`readUrl()` 的返回值也顺带没人用了。

## 探针侧：修掉一处会「假通过」的硬编码

`_check/raceprobe.js` 的快照里写着 `fieldValue(31.2304, 121.4737)`。
值场只有查询点周围 500 km，默认城市一换，这个点落到场外 → `fv` 恒为 `null`
→ `staleAll` / `maskOffOk` 的比较全在拿 `null` 互相比较、一律为真
→ **竞态断言静默退化成空转，却依然"全绿"**。

改法：
- 指纹改取 **`MapMod.gridC`（取数时真正用的网格中心）**，回退到 `State.lat/lon`；
- `fieldAtSH` 键名改为 **`fieldAtC`**（它本来就不该叫上海）；
- **加自守护**：`fieldAtC === null` 时打印「探针失效」并以非 0 退出 ——
  以后任何"值场取不到值"的情况都不会再伪装成通过。

`_check/cdp.js` 里同一类硬编码三处（悬停连发 40 次、点击钉卡、切模型后取提示卡文案）
改成以 `State.lat/lon` 为基点的相对偏移。其中悬停那条**断言本来不受影响**

"测的是一个空位置还能画提示卡"，没有意义，所以一并改。

# 下一步改进方案（纯分析，未改任何产线代码）

产出 `下一步方案.md`。为写这份方案做了四项**实测**，不是纸上推演。

## 实测一：计费式钉死了

**`加权调用 = max(1, 变量数/10) × max(1, 天数/14) × 坐标数`**

四个实测点全部对上：单点 14变量/3天/17坐标 = 23.8；单点 AQ = 17；地图 9变量/1天/57 = 57；
地图 AQ = 57 → 合计 235.6 ≈ 236 ✓。官方 FAQ 示例同样吻合（15变量×2周 = 1.5、×4周 = 3.0）。

**推论（很重要）**：单点（3 天）与地图（1 天）的**时间系数都已踩在下限 1.0**，
所以"缩短时间窗"省不到任何额度 —— **唯一有效的杠杆是变量数**，而 >10 变量才会跨过计费阶梯。
这条推翻了"再压一压时间窗"的直觉方向。

## 实测二：单点与地图中心口径不一致（真实接口，`_check/consistency.js`）

同一地点同一天同一时段：

```
单点  P/Q/I : 25.6 / 27.8 / 26.6     ← computeAll，TRANSECT 17 点全真实取数
地图  P/Q/I : 22.8 / 26.8 / 24.6     ← loadMapData，trOf() 只有 2 点（d=0 真实 + d=250 IDW）
差值  ΔI = -2.0 分
```

根因是结构性的：`analyseTransect` 在 2 点样带上只能分辨"0 / 250 km 两处有没有云"，
云边界距离被压成两档。差值本身不大，但**用户在地图中心悬停就能看见与上方大数字不一致**。
修法零取数（`trOf()` 加密到 3–5 点，中间点同样走 `idwSample`），
但值场数值会变 → **必须升 `MAP_CACHE_PREFIX` v4→v5**。

## 实测三：多模型合并请求可行，但**不建议做**

`models=gfs_seamless,ecmwf_ifs025` 一次请求 HTTP 200，响应把变量名加 `_gfs_seamless` /
`_ecmwf_ifs025` 后缀，一个坐标拿到两套模式。但合并后变量数 9→18，**跨过「>10 变量」计费阶梯**，
单坐标权重从 1.0 跳到 1.8；而"模型数是否另行相乘"官方未明说。收益不确定、风险确定 → 不做。

## 实测四：单点请求里有一个从没被真正需要的变量

`F_VARS` 有 14 个，其中 `dew_point_2m` **是冗余的** —— `buildEnv`（`_p4.js:268`）本来就有
`Td = T - (100 - RH)/5` 的兜底，地图侧 `F_MAP_VARS` 正是靠这条把变量压到 9 个的。
删掉它：14→13 变量，权重 1.4→1.3，每页省 3.4 个加权调用，**零精度损失**。

逐个核对过其余变量是否真被用到：`cape`(4 处)/`precip`(2)/`vis`(5)/`fz`(2)/`blh`(2) 都在用；
`pressure_msl` 虽只被 `pressureTrend` 用一次，但那正是 `W_STAT.stab` 的输入，**要留**；
`gust`/`sw`/`cloud_cover`(总) 是 optional、缺失不报错，本来就没请求。

## 方案的判断：重心该从「省额度」转到「口径一致 + 可信度表达」

首屏 65（≈154 次/天）、全量 236（≈42 次/天）—— 对个人使用已经够用，继续抠额度边际价值很低。
而"结论卡与地图打架"是用户能直接看见的。所以：

- **批次 A**：A1 地图样带加密（唯一一项用户可见的矛盾，零取数）
- **批次 B**：B1 分享卡导出 PNG（纯 canvas 手绘，零取数）/ B2 可信度徽标提到台面 /
  B3 单点侧统一模型分歧口径 —— 三项都零取数，数据早在 `State.result` 里
- **批次 C**：C1 气溶胶隔点取样 —— **只在量化通过后做**（AOD 空间相关尺度 vs 120 km 间距，
  以及 `aeroF` 的非线性），量化不出来就不做
- **E1**：`_check/all.py` 一键跑 10 个探针（现在全是手动按序跑，漏一个"全绿"就没依据）
- **明确不做**：砍单点变量到 10 个 / 合并多模型请求 / 逐日动画 / 可信度做成色面透明度 /
  拉长 `MAP_CACHE_TTL`（3h 已贴着 GFS 每小时更新，再拉长会拿到过期模式场）

**这一整批几乎不需要多花任何额度。**

删掉是**主动引入损失**，不是零损失。

## A1 —— 根因比"样带点数少"更本质

症状：单点 P/Q/I = 25.6/27.8/26.6 vs 地图中心 22.8/26.8/24.6，**ΔI = −2.0**。

根因是 `analyseTransect` 的 `step` 依赖：旧地图 2 点样带 ⇒ `step = 250` ⇒
开边界 `dFar = 250 + 250 = 500 km`，而单点 `TRANSECT` 同口径是 `400 + 25 = 425 km`。
**步长不同 ⇒ 同一片云算出不同边界距离**。

改成与单点完全同构的 17 点后：**ΔI = −0.9**（达标）。余下 0.9 是"真实采样 vs IDW 插值"
的精度差，不是口径差。

性能坑：`idwPlan` 按**目标点**预算权重、`idwOf` 套到任意变量上。
若照 `idwSample` 每变量各算一遍 → 57×16×4×2 ≈ 150 万次球面距离，会卡住取数。降约 23 倍。

## B2 / B3 —— 把"可信度"和"分歧口径"收敛到一处
