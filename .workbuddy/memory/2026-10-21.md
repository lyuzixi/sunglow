## 7. 时刻改为「所选城市的当地时间」（同日追加）
**发现的两个真 bug（同一根因：没有城市时区模型）**：
1) **显示**：`uClock` 用 `new Date(ms).getHours()` = 浏览器时区。实测纽约日落显示 06:06（真实 18:06 EDT），东京差 1 小时。北京「恰好对」只因为浏览器也在 UTC+8。
2) **取数**（更严重）：`timezone=auto` 下 Open-Meteo 返回的是**城市墙钟字符串**，代码用无后缀 `Date.parse` 当浏览器本地解析；而查询用的是真实太阳时刻。两者差「浏览器偏移 − 城市偏移」：东京取到日落前 1 小时的数据，纽约 +12h **越过序列末端被 clamp 到 23:00**。证据：纽约「能见度 27.5km」= 当地 23:00 那格（18:00 应是 45.6km）→ 外城市 P/Q 一直是错小时算出来的。
**方案（grill 定稿）**：新增 `src/core/tz.ts`，唯一时区来源 = 响应里的 `utc_offset_seconds`（数值，快照/缓存）+ `timezone`（IANA 名，显示走 Intl 算夏令时）。**序列时间一律存真实 epoch**，只有显示的最后一刻折算墙钟。首屏未知时经度估算（中国全境先特判 +8）+ 按坐标 0.1° 记住实测值（`glowcast.v2.tz.*`）。默认日期/月历范围/地图日期列表全按城市当地「今天」；跨时区才在时刻旁标 `UTC−4`（国内城市不出现任何多余字）。
**两个实现坑（都是「量纲/精度」级别）**：
1) `offsetAt` 里 `Intl` 的**秒是截断的**，而太阳时刻带小数毫秒（二分法）→ 相减稳定少 1 秒 → 再 round 成整秒误差（28800 变 28799，标签渲染成 `UTC+7:59`、时刻整体错 16 分钟）。必须先把真实时刻 `Math.floor(ms/1000)*1000` 再相减。
2) 同一处算出来的是**毫秒**，忘了除 1000 直接当秒用 → `UTC+8000`。而整小时偏移的「秒当毫秒」会恰好模出正确的小时（28800000s mod 86400 = 8h），**显示看着对、标签是错的**——只断言时刻会漏掉这个 bug。
**缓存与快照**：点缓存 `point.v1 → v2`、地图 `map.v6 → v7`（旧条目自动失效）；快照**追加第 22 位**真实偏移（老解码器只读前 21 位，与原版互通不破），解码时 21 位的老快照按坐标重算，不信那个恒为 480 的假值。`rememberedTz`/`pointCacheGet` 都加了「偏移必须是 15 分钟整数倍」的脏值拦截。
**验证**：`npm run probe:tz`（新增，纯 Node + esbuild，不联网不进 DOM）**28 条全绿**；`probe:ui` 79 → **88 条全绿**（北京 17:26 无标注 / 东京 16:58 UTC+9 / 纽约 18:06 UTC−4，且天色带首刻度与结论卡一致）；`probe:consist` 16 点仍一致；typecheck 干净，构建 705.5 KB 零外链。

## 12. 缓存机制审计 + 四项额度修复
**用户问「为什么次数消耗很快」** → 用假成功 fetch 桩（回合法 JSON，不烧真额度）实测真实请求数，按 Open-Meteo 官方权公式折算加权调用：**单点 = max(1, 变量数×模型数/10 × max(1, 天数/14))，按坐标数累加**。

**grill 四项决策**（用户选定）：地图改日期不自动取数 / 修重试策略 / 两个加载按钮缓存优先 / TTL 3h→6h；命中交互 = **用缓存 + 旁路小字「缓存 · N 分钟前」+「重新取数」文字入口**。补充拍板：① 换日期未命中 → **清空图面 + 提示「该日期尚未取数」**（绝不让新日期顶着旧日期的图）；② **AOD 不动**（用户在「抽样取 / 整路不取 / 不动」里选了不动，接受 1/3 额度成本）；③ 缓存提示**三处统一**（地图 / 趋势 / 结论卡）；④ 额度说明**写真实数字**（单点 51 / 地图 171 / 趋势 102 / 免费层 10,000 每日按出口 IP）。

**改动**：
- `mapload.ts` `jget` 重试收紧：**429 一律不重试**（限流时重复请求只会加长封禁，注释里专门写了「这里绝不能写反」）；有 `retry-after` 就听服务端的但 >3s 直接报错；超时/网络/5xx 最多再补 1 次。最坏请求数 3 → 2（限流 3 → 1）。`api.ts` 的 `jget` 默认 tries 同步 3→2（死代码路径，但口径要一致）。
