## 第五轮反馈：桌面端地图全屏后无法退出（sticky 层叠陷阱）

- **用户反馈**："电脑的地图全屏后也无法退出。做成和手机一样的退出交互。"
- **根因**：`.mapwrap.fs` 的 `z-index:2100` 看着高于 `.top` 的 60，却被顶栏整片盖住——
  地图卡 `#cardMap` 自己是 `position:sticky`，**sticky 必然自建层叠上下文**，2100 被关在
  卡片内部，整张卡只以 `z-auto` 参与页面层序，反而排在 `.top(60)` 之下。全屏后 67px 高的
  顶栏压住左上角退出胶囊（rect [10,10,96,36]）：rect 在视口内、display 正常，点击落在
  `.top` 上什么都不会发生。手机端 `.top` 是 `static`（z-index 不生效）所以从未复现——
  这正是"只有电脑退不出去"的原因。第四轮的 `#map{position:relative;z-index:0}` 钳制的是
  SDK 内部层，与这个陷阱是两件事，别混。
- **复现手段（可复用）**：`map.qq.com/api/gljs` 在本机可达（瓦片鉴权失败不影响控件 DOM）。
  本地 HTTP 起真实页面 + CDP `Input.dispatchMouseEvent` **真实点击** + `elementFromPoint`
  命中链，桌面端命中 `div.top → span → #fsExit`，手机端命中 `span`。脚本存
  `_scratch/fsrepro.js`（最小复现页）、`fsrepro2.js`（真实页面端到端）、`fsrepro3.js`
  （祖先层叠上下文链 + 双端对照）、`fsshot.js`（修复前后实拍）。
- **修法**：`setMapFs` 挂摘 `#cardMap.fsmap`，CSS `#cardMap.fsmap{z-index:2200}`
  （.mapwrap.fs 同族、仍低于抽屉类浮层）。全项目只有 `setMapFs` 一处切 `.fs`。
  效果与手机一致：地图铺满视口、左上角胶囊真实可点；Esc 路径不受影响。
- **探针补硬（本次漏检的直接原因）**：mapaudit L 段原来用 `b.click()` 退出——合成点击
  **绕过浏览器命中测试**，按钮被盖住时照样能退，所以一直是绿的。新增两条判据
  （48 → **50 条**）：① `elementFromPoint` 在胶囊中心必须命中胶囊本身；② 全屏期间
  `#cardMap` computed z-index 必须为 2200、退出后回 auto。退出动作改为 CDP 真实点击。
- **踩坑**：探针断言里把 `L3.afterCardZ` 误写成 `L.afterCardZ`（恒 undefined）→ 判据假红；
  README 表格编辑吃掉换行把两行并一行。docfacts 同步：mapaudit 50、源码 11,180 行
  （_p6 4,063 / template 1,630）、产物 794,736 字节。
- **结果**：`all.py` 25/25 PASS · 0 FAIL；实拍对照 `_scratch/fs-desktop-before.png`
  （顶栏吞掉胶囊）/ `fs-desktop-after.png`（胶囊可见可点）。总结文档追加 §17。
- **未提交**：本轮改动全部只在工作区（template / _p6 / mapaudit / README / 阶段性总结 +
  重建产物）。上线需另走部署。
