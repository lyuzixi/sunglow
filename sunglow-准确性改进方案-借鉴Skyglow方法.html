sunglow 预测准确性改进方案
——Skyglow 可迁移方法系统分析

按数据预处理、特征工程、模型结构与超参数、训练与验证策略、后处理与误差分析五个维度，逐项盘点 Skyglow 中经实证的方法，分析其对 sunglow 预测任务的适配方式，并给出按优先级排序的改进建议、预期收益与验证指标。

P0 先建度量，再谈改进 标定层并联，不动主口径 浏览器可推理 · 权重即常量 缓存版本号 + 探针期望同步演进
核心主张：sunglow 当前模型是「物理量 + 手工隶属函数 + 固定权重」，结构透明但无自证能力（仓库内未见实测标签回测）。Skyglow 最值得迁移的不是某个公式，而是一整套「可标定、可验证、可归因」的工程方法：用 1109 条实测标签做岭回归标定（AUC 0.80 vs 参考 0.76）、按日期分组交叉验证、分位阈值、误差案例归档。迁移的总策略是「并联而非替换」——保留手工模型为参照口径（守住 probe:consist 与「算法V1唯一权威」硬约束），把标定层作为第二条独立意见接入 sunglow 已有的 refGap 式分歧展示框架。

0目标与硬约束

先明确「提升准确性」在 sunglow 的语境里意味着什么，以及哪些仓库自设的约束决定了改进只能以特定形态发生。

0.1 目标分解

目标层含义对应指标（§4 定义）
概率校准报 70% 的事件，实际应有约 70% 出现（当前 logistic(6.5(S−0.62)) 的 (6.5, 0.62) 为手工设定，无标签拟合）Brier、ECE、可靠性分箱
排序判别「哪天/哪点更值得去」的排序正确性AUC、Spearman、±1 档命中
等级贴合优/良/一般/差四档与真实分布对齐完全命中率、混淆矩阵
可信度诚实不确定的时候敢说「不确定」置信度分档 vs 实际偏差（F4 闭环）

0.2 sunglow 的四条硬约束（改进方案的前提）

约束内容与出处对改进的形态约束
口径冻结「算法V1唯一权威」：W_ENS/TRANSECT/mixedIndex/QUALITY_BANDS 等常量单一来源；v2/v3 为逐语义移植；probe:consist 活守卫 架构文档 §8.6 · v2/src/core/scoring.ts 文件头「禁止调整」任何改变 P/Q 数值的改动，必须走「V1 _p*.js 与 v2 src/core 双落 + 探针期望更新」；不能只改一侧
浏览器推理全部计算在前端完成；无 numpy/无服务端 README §1标定后的模型必须可纯 JS/TS 前向（矩阵乘法+sigmoid 可行；Skyglow 的 nn.py 50 行已证明同构可移植）
缓存版本纪律「权重/阈值一改旧缓存就错」——用键内版本号兜住 README §5 趋势缓存段模型参数变更必须同步递增 POINT/MAP/TREND 缓存前缀，旧条目自然作废
额度访客侧取数按访客出口 IP 计；429 双分类文案已内置 v2/src/core/mapload.ts:57-67改进不得增加请求量；评测集构建只能在离线工具侧进行
总策略所有建议按「并联第二意见 → 验证占优 → 再谈切换」推进：第一阶段任何新模型都只作并列展示（sunglow 已有 refmodel 旁证与 refGap 分歧展示的产品先例，v2/src/core/refmodel.ts、mapdata.ts:94-111），主口径数值不动；只有当并联版本在 §4 指标上稳定占优，才启动「双落切换」流程。这把「打破口径冻结」的风险降到最低。

3按优先级排序的改进建议

优先级判定标准：① 是否为后续一切改进的前提；② 对硬约束的冲击面；③ 收益/工作量比。每条含做法、预期收益、验证指标与风险对冲。

P0-1

建立评测集与指标基线（一切改进的前提）

做法
在 v2/tools/ 新增离线脚本三件套（Skyglow 同构移植，均为纯 stdlib/TS，不碰线上）：① 抓 sunsetbot.top 上海站再分析标签（移植 tools/fetch_reanalysis.py，10 天窗口自适应）；② 抓同期 17 样带点 ERA5 历史场（移植 tools/fetch_grid.py，注意 sunglow 只用 Forecast 端点，历史场需走 Archive——这会新增一个数据域，需在报告中注明）；③ 用 sunglow 自己的 forecast/scoreStat/scoreRay 对每个 (日期, 事件) 重算特征与输出，构建 (特征, 标签) 表。先出基线报告再动手改模型：现有手工模型在同一评测集上的 AUC/Brier/±1 档就是所有后续改进的对照组。
预期收益
把「准确性」从主观变为可度量；后续每条建议都有 A/B 判据。Skyglow 在同源标签集上做到 CV AUC 0.802 / Brier 0.118（五折）、时间切分 AUC 0.797 / Brier 0.167（data/validation.json）——这是同任务的可达性参照，不构成对 sunglow 的承诺。
验证指标
评测集规模（目标 ≥1000 条标签 × 2 事件）；基线指标六件套（AUC/Brier/±1/完全命中/TSS/可靠性）成文入库。
风险与对冲
标签单站（上海）→ 报告中显式标注适用范围，跨气候区结论不外推；Archive 端点取数一次性离线完成，不增加线上请求。
P0-2

一维概率标定：把 (6.5, 0.62) 换成标签拟合的 (a, b)

做法
保持 S=wgeo(9 因子) 与整个评分结构逐字不变，仅把 P=100·logistic(6.5·(S−0.62)) 的两个常数改为在 P0-1 评测集上用牛顿法拟合（移植 tools/calibrate.py:88-115 的 fit_logistic_1d，约 30 行）。因 P 的数值会变，需同步：① V1 _p4.js 与 v2 scoring.ts 双落；② 递增 POINT/TREND 缓存前缀（v2 已有该纪律）；③ 更新 probe:consist 与相关探针期望值。若暂不动主口径：可先以「标定值 vs 手工值」并列展示一周，用 F4 本地校准的 obs−pred 偏差做产品内验证。
预期收益
概率校准（Brier/ECE）显著改善——这是全部建议中改动最小（两个常数）、收益最直接的一条。参照：Skyglow 的 (prob_a, prob_b)=(2.66, 1.38) 即由同法拟合；一维 Platt 标定在概率校准上的改善是稳健结论（此为方法学通识，非本项目实测，标注为假设 A2）。
验证指标
Brier（目标 ≤ 基线 −10%）；ECE（十分位）；可靠性曲线斜率（目标接近 1）；AUC 应持平（标定不改排序）。
风险与对冲
标签分布漂移（Skyglow 自述：训练期基率 13.3% vs 测试期 24.3% 导致秋季偏保守）→ 按季节分箱检查可靠性曲线，漂移可见时在 UI 注明；双落流程漏一侧 → probe:consist 兜底。
P1-1

岭回归标定层：并联的「第二条独立意见」

做法
新增 core/calib.ts：输入 = FacCtx 原始量（cover/base/hEff/d/xMax/lowBlock/aod/vis/rh/dP/windComp/cape/precip，约 12–14 维，缺失保留 null），logit/log 变换（移植 Skyglow _raw_features 思路）→ z 标准化 → Ridge（α 网格 0.3/1.2/3.0）→ 潜变量 → 一维 logistic → P_calib。权重以 JSON 常量内联（Skyglow model.json 模式，单文件构建已支持内联）。并联接入：与物理核并列显示、差值驱动色面降饱和——sunglow 已有完全相同的产品机制（refmodel + finalizeRefGap 的 z 分数形态分歧，v2/src/core/mapdata.ts:94-111），新层只扩展该框架，不新增 UI 概念。
预期收益
排序与等级判别提升（AUC/±1 档）。Skyglow 在同源标签上 AUC 0.80（参考预报 0.761）、±1 档 81.6%（五折）——同任务参照上限；预期 sunglow 获得方向性改善但幅度需实测（假设 A2）。
验证指标
AUC（并联路 vs 主口径，非劣效 → 优效两级判定）；±1 档命中；与主口径的 refGap 分布（分歧不应系统性单边，否则说明尺度未对齐）。
风险与对冲
过拟合（样本仅千级）→ Ridge + 日期分组 CV + 消融（P1-3）；特征泄漏（把 spread/dvI 等「事后量」当特征）→ 特征清单评审，只取事件时刻可测量；口径争议 → 并联期不动任何既有数字。
P1-2

特征工程三件套：离散度入置信度、logit 空间组合、缺测显式化

做法
① spread 入置信度：在样带各点计算中/高云量标准差（Skyglow core/meteo.py:343-351），与三路 dvI 并列喂 ensConfOf——回答「这一片云本身匀不匀」，与「三模型吵不吵」是两个独立的不确定源；② logit 空间组合：wgeo 在 [0,1] 空间做几何平均，概率输出域不对称，改用 logit 后加权线性组合（Skyglow core/model.py:174-192），使组合结果天然落在概率域；③ 缺测显式化：主口径 wgeo 目前对 null 因子静默跳过（等于「按已给项重归一化」，已接近正确），补上两件事——缺测项在因素表标注「未参与计算」（refmodel 已有 missing 列表可复用）、AOD/vis 缺测时置信度降档（Skyglow core/service.py:26-27 同法）。
预期收益
置信度与真实偏差的相关性增强（F4 闭环可验证）；组合函数换域后 P 的校准性改善（与 P0-2 叠加）；缺测不再被「静默平均」掩盖。
验证指标
置信度分档（高/中/低）与实际 obs−pred 偏差的单调性；换域前后 Brier/可靠性对比；缺测场景的 UI 覆盖率。
风险与对冲
② 改变 S 的数值 → 与 P0-2 合并为一次双落，避免两次动口径；三项都先用探针断言「非缺测路径数值不变」再放开缺测路径。
P1-3

训练与验证纪律：时间切分、日期分组 CV、消融实验

做法
把 P0-1 评测集用对：① 一律时间切分（禁随机划分）；② 五折 CV 按日期分组（同一天样本不跨折，防云量自相关泄漏）；③ 指标六件套 + TSS 阈值扫描 + 可靠性分箱；④ 特征集消融（A–F 模式，移植 tools/experiment.py）；⑤ 与 sunsetbot 同期预报基准对照。全部离线跑，产出与 Skyglow validation.json 同构的报告文件，可被现有 docfacts 式纪律守护。
预期收益
防止「自欺式指标」（训练集内评估）；特征取舍有据（消融）；给出可持续追踪的精度基线。
验证指标
评测流程可一键复跑；报告含 train/val/test/CV 四组数字；任何模型变更必须附新的消融结论。
风险与对冲
无。
P2-1

MLP 旁证（数据驱动第四意见）

做法
离线 numpy 训练（移植 tools/train_nn.py：15-8-4-1、tanh、He 初始化、全批量 Adam、L2、早停）；推理用 TS 前向约 50 行（Skyglow core/nn.py 已证明同构）；权重 JSON 内联。接入点同 P1-1：并列展示 + 分歧度量。前提：P0-1 完成且标签 ≥1000 条。
预期收益
与光追/统计/标定层方法学独立的第四条意见，分歧本身即风险信号。参照：Skyglow MLP 测试 AUC 0.794（与其物理模型 0.797 接近），但训练 AUC 0.881 → 其自述结论是「只作交叉参考」；sunglow 若标签量相当，结论大概率相同（假设 A2）。
验证指标
测试 AUC/Brier（与 P1-1 并联比较）；四路分歧极差分布；训练/测试 AUC 间隙（过拟合哨兵，>0.05 触发降级为仅展示）。
风险与对冲
过拟合 → 早停 + 早停哨兵；浏览器体积 → 权重瘦身（Skyglow make_single.py 只内联 version/features/mean/std/W/B）；不作任何加权合成，永不打分。
P2-2

阈值分位重标 + 误差案例归档 + 分布漂移监控

做法
① QUALITY_BANDS 的 80/65/45 改按标签分位点确定（Skyglow tools/calibrate.py:217-226），使四档人数比贴合真实分布；② 建「误差案例」自动清单（命中/漏报/空报各 Top-N，Skyglow validation.json cases 段同构），进回测页；③ 漂移监控：按月份/季节分箱报告基率与预测均值之差（Skyglow 发现的「秋季偏保守」正是此机制抓到：训练期 13.3% vs 测试期 24.3%）。
预期收益
四档分布对齐（完全命中率提升）；漏报/空报有据可查而非凭印象；季节漂移在产品内可见。
验证指标
分档人数比 vs 标签分布（卡方/最大偏差）；漏报率、空报率按月曲线；回测页案例数与探针覆盖。
风险与对冲
① 改变产品可见等级 → 列入双落切换阶段，切换前并联对比 ≥2 周。
P2-3

上游采样侧向加密（不改请求数的前提下）

做法
sunglow 样带是沿太阳方位的 17 点单线（0–400 km）；Skyglow 用 25 点环带（3 环 × 8 方位）覆盖整个上游扇区，其实测依据是「仅中心点最差偏差 42.3pp」。适配方案：保持 17 点请求不变（额度纪律），在已取回的格点数据上做「样带 + 两侧 ±30°/±60° 短射线」的加权聚合近似；地图场景则利用 121 点网格天然具备侧向覆盖（可验证是否需要增强）。
预期收益
horizon/block 类因子（光路上游）分辨率提升，直接命中「太阳方向上游低云」这一最坏误差源。
验证指标
P1-1 消融中「上游聚合方式」单独成组；用 P0-1 评测集比较 17 点单线 vs 加密聚合的 AUC/±1 档。
风险与对冲
只改聚合不改取数 → 不影响额度；数值变化并入 P0-2/P1-2 的同一次双落。

6明确不做清单（含理由）

  • 不做 ECMWF/GFS/ICON 官方档案 GRIB2 直连：浏览器物理不可达（eccodes 是 C 库），属 Skyglow 服务端专属能力。
  • 不做 ERA5 历史回溯前端化：同上；sunglow 的日期窗 today−7～+10 是形态选择而非缺陷，历史复盘需求由 Skyglow 承担。
  • 不引入第五个概率源或把总云量拆三层：sunglow 与 Skyglow 在这点上结论一致——辅助源只有总云量，硬拆等于编造模型最依赖的量。
  • 不做「多源任一达标即报警」的并集策略：sunglow README 已论证其系统性抬高空报率，对拍摄决策有害。
  • 不在浏览器端训练任何模型：训练一律离线工具侧；前端只做前向推理。
  • 不替换手工模型为纯数据驱动模型：物理可解释性是 sunglow 的既定产品属性（因素表 13 项逐项解读），标定层是「重新加权」而非「换掉物理核」——与 Skyglow 模块 docstring 的自我定位一致。
  • 不为改进增加任何线上请求量：全部特征来自已取回数据；额度纪律优先于精度提升。
