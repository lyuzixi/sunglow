SUNGLOW · 使用教程

让每一次追霞，都有迹可循

读懂朝霞与晚霞的预报

霞光档案 · SUNGLOW 是一个单文件 Web 应用：输入地点与日期，预测朝霞 / 晚霞（火烧云）出现的概率与观赏质量，并在周边 80 km 采样网格上画出霞光分布。这份教程分四档，按身份取用。

三模型综合

GFS 与 ECMWF 两路统计判据加一路光追物理模型，各自打分后按权重几何平均合成；三路分歧度直接换算成可信度。

光谱观测场

以查询点为中心的 121 点网格，全光谱色阶铺色，可切换出现概率 / 观赏质量 / 云量 / 可信度四个维度。

十日趋势

一次取数画十天曲线，朝 / 晚分开看；算好的结果落盘缓存，重开页命中零请求。

多观测点对比

最多 4 个机位一次取数横向排序，直接回答「今晚去哪儿拍」。

快照互通

结论编码进 URL，对方打开即见快照、零额度零请求；快照格式与 V1 完全互通——两边生成的链接互相能解。

01快速开始

  1. 选地点：搜索城市名，或直接输入「纬度,经度」。
  2. 选日期与时段：日期可回看 7 天、前瞻 10 天；朝霞与晚霞分开计算。
  3. 读结论：概率 + 质量分 + 等级 + 可信度；往下拉是十日趋势、观测场与多观测点对比。

02版本家族

霞光预报家族三套并存、互相隔离：V1（仓库根目录的原版，单文件 assemble 构建链，算法权威）、SUNGLOW v2（本教程所属，项目主线）、Skyglow（Python 服务端版）。页脚「切换到V1」随时回到原版。

用户版

十分钟看懂这份霞光预报

每个功能怎么用、每个数字怎么读。不需要任何气象背景。

01查一次预报

顶部搜索框输入城市名，或直接给「纬度,经度」；日期选择器可切到过去 7 天内的任意一天与未来 10 天；朝霞 / 晚霞在结论卡上方切换。

位置与日期不写进偏好——每次打开都是新的开始；想带走当前结果，用分享链接。

02读懂结论卡

出现概率＝今晚「有没有霞」；观赏质量＝「好不好看」（0–100 分，优 ≥80、良 ≥65、一般 ≥45）。两个维度独立：概率高可能质量平平（闷烧），概率低也可能一旦出现极惊艳。

卡内天色带标出日出 / 日落与民用 / 航海 / 天文昏影终四道线，「此刻」游标告诉你正处在哪个阶段；晚霞的黄金窗口通常在日落后 10–25 分钟，朝霞则要赶在天亮之前到位。

三张模型卡（GFS / ECMWF / 光追）可逐张对照：结论越一致，可信度徽标越稳；分歧大时，宁可当「可能有」对待。

03十日趋势

点「加载趋势」显式取数（约 102 次加权调用，34 个坐标 × 10 天一次拉完），之后朝 / 晚两条概率曲线加质量分柱状列。算好的结果落盘缓存 6 小时，重开页命中直接画出，零请求。

04观测场地图

以当前地点为中心的 121 点采样网格（80 km 间距），四种着色维度：出现概率 / 观赏质量 / 云量 / 可信度。色阶是全光谱形态——颜色即数值，没有凸包硬边界，边缘自然淡出。

取数纪律：只有显式点「加载周边地图」才发起请求（约 171 次加权调用）；这个日期已有缓存时会自动画出来。选点有两种方式——直接点格点，或搜城市名；任意点都能一键「加入对比」。

05多观测点对比

最多 4 个点。从地图格点加入的免额度（读已取数的场）；搜索加入的每个点约 51 次加权调用，缓存 6 小时。一次取数后按质量分横向排序——「今晚去哪儿拍」就此有答案。

06保存图片与快照链接

结论卡的「保存图片」导出 PNG 结论卡（纯 canvas 绘制，配色跟随当前主题）；「复制链接」把当前结果编码进 URL（base64url，SNAP_VER=1），对方打开即见快照，不消耗任何接口额度。格式与 V1 互通——V1 生成的快照这里能解，反之亦然。

07实况校准

看完霞回来标注「看到了 / 没看到 / 无法判断」。本机在你的区域加同档概率下累计样本，≥8 条且本档 ≥3 条时展示观测偏差。校准只在本机展示，绝不回改预报模型；关掉标注开关不会删除已有样本。

08偏好与外观

设置面板里：主题（大气光谱观测站·深色 / 晨光实验室·浅色 / 跟随系统）、语言（简体 / 繁體 / English）、单位（公制 km·m·℃ / 英制 mi·ft·℉）、时间格式（12 / 24 小时制）。偏好写本机 localStorage，与本教程页共享同一份。

09缓存、额度与离线

所有结果按「日期 + 时段 + 坐标」分键缓存 6 小时，设置里可看条数、一键清除。数据源 Open-Meteo 免费层按访客 IP 计额度，遇到 429 时限流不自动重试。网络不可用（预算 9 秒）会回落到确定性 mock，界面左上角标注 MOCK——别把 mock 当预报。装了 PWA 的话，断网也能看已缓存的结果。

开发者版

构建、口径与质量门

从一条构建命令到三套算法的口径细节，读懂 SUNGLOW v2 的全部机制。

01形态与构建链

源码在 v2/，交付物是一个自包含单文件。一条命令跑完构建与发布：

cd v2 && npm run build

三段接力：vite build 把 JS/CSS/字体全部内联进 app.html；emit-single.mjs 落成 v2/index.html 并把引用还原成稳定文件名（残留哈希即构建失败）；publish-root.mjs 把 7 个交付文件发布到仓库根并逐文件 sha256 校验。产物禁手改；根 index.html 即 GitHub Pages 入口。

vite build

publish-root

02源码结构

src/core 的 TS 模块按职责分层：取数与编排（api / forecast / trend / mapload）、算法（scoring / physics / astro / refmodel / skyband / verdict）、地图（mapdata / maprender / ramp / popover）、状态与协议（state / snap / urlstate / cache / calib）、展示辅助（i18n / city / citylang / cityname / units / tz / series / sharecard / compare / math）。

vendor/src-verbatim/ 是 V1 七脚本的冻结副本：不参与构建、不加载，只作口径 diff 基线。V1 算法若演进，先 diff 该目录再同步 src/core。

03算法口径

统计判据路（GFS / ECMWF）：云量、云型、云底高度、气溶胶等要素加权打分（因素面板列全 13 项判据，末项为模式一致性）→ P；光追路：沿地球曲率的抛物线光路做逐波长消光积分，用 CIE 1931 色度函数算出真实色彩 → Q。两路先合成 mixedIndex，再三路集合：

mixedIndex = 0.55·P + 0.45·Q W_ENS = GFS 0.30 / ECMWF 0.34 / 光追 0.36（几何平均） 可信度 = 三路极差分档：<18 高、<35 中、≥35 低

一切口径与 V1 逐点对齐；任何改变 P/Q 数值的改动必须双落（V1 _p*.js 与 v2 src/core 同步改），并由探针守着。

04与 V1 的关系

算法权威在 V1（仓库根 V1/ 目录）。probe:consist 不重写公式，而是从两边源码把同一表达式原样抽出来 eval，在 16 个采样网格上对拍——任何一边改了口径，脚本立刻报差异，相当于一条活的口径守卫。

两侧状态完全隔离：localStorage 键 sunsetbot.*（V1）vs glowcast.v2.*（v2）；快照 SNAP_VER=1 双向互通，任一侧生成的 ?snap= 链接对方可解。

07快照与 URL 协议

?snap= 后接 base64url 编码的结论快照（SNAP_VER=1），零气象请求还原整张结论卡；语言进 URL（?lang=zh/hant/en），主题不进——分享链接即对方能看懂的版本。

08质量门：探针与纪律

npm run typecheck # tsc --noEmit npm run build # 构建 + 发布校验（缺文件/残留哈希即失败） npm run probe:ui # agent-browser 驱动，约 280 条断言 npm run probe:tz # 时区口径 28 条 npm run probe:consist # V1↔v2 口径对拍 16 采样点

全仓 LF 行尾；改产物必须重跑构建；探针跑的是构建产物，不是源码——忘重建等于测旧代码。

09部署

交付物在仓库根（publish-root 每次构建自动刷新）。GitHub Pages 项目页开在子路径，单文件形态 base 为相对路径，任意静态托管都能开。

地图代理占位符 __TMAP_SERVICE_HOST__ 由构建期环境变量 VITE_TMAP_SERVICE_HOST 注入，产物不含任何密钥；未注入时回落占位符——地图不可用，但查询 / 趋势 / 分享卡全可用。PWA 注册靠 link[rel=manifest] 存在性判断，SW 绝不缓存气象响应，缓存名随产物内容哈希自动作废。

创作者版

用预报数据规划一次拍摄

从选日子到出图，把霞光预报变成你的拍摄计划表。

01三步挑一个拍摄夜

  1. 十日趋势挑日子：概率与质量双高的那天值得专程出门；只看概率会赶上「有霞但不好看」。
  2. 结论卡卡时间：天色带四道线里找你的窗口——晚霞黄金 10–25 分钟，朝霞赶在天亮前；「此刻」游标告诉你还剩多少准备时间。
  3. 观测场挑点位：切到质量维度找颜色最亮的格子，切云量维度绕开灰的——点位选对，等于提前一小时到位。

02结论卡导出

结论卡的「保存图片」一键导出 PNG：概率大字、天色带、三模型结论都在一张图上，纯 canvas 绘制、配色跟随当前主题。深色 Spectrum 卡适合直接发社交平台；浅色晨光卡适合打印或贴进拍摄计划表。

03快照链接做内容

「复制链接」得到的 URL 自带完整结论：对方打开零额度、零等待，语言跟着链接走。V1 用户也能解你的快照——跨版本内容可以互相引用，老读者不会丢。

04主题与截图

两套主题都是为出片调的：大气光谱观测站（深空蓝黑加光谱渐变）适合夜景氛围长图；晨光实验室（浅色）适合白天阅读与归档。截图前把时间格式切到你习惯的那档（12 / 24 小时制），时间戳更齐。

05实况校准的反哺

每次拍完回来标注「看到了 / 没看到 / 无法判断」。本机样本攒够后（≥8 条），你会看到自己所在区域的观测偏差——那是你的个人命中率，比通用概率更懂你的机位。数据只存本机，换浏览器不跟着走。

06额度礼节与离线

别用脚本刷接口——免费层按访客 IP 计额，刷爆了大家都没得看。出门前把常用城市看一遍，断网时已缓存的结果照样能开；PWA 装上之后，山里也有底气。
