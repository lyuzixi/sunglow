演示素材

它到底在算什么

一句话：把「今晚有没有火烧云」从玄学变成可量化的概率与质量分。

朝霞 / 晚霞
日出前与日落后的低空霞光（火烧云）。两者的大气条件不同，所以应用分开预报、可分别切换。
概率 %
出现霞光的可能性，由天气条件（云量、湿度、能见度等）推算，不是「会不会出太阳」。
质量评分
在「会出现」的前提下，霞光的观赏质量（色彩浓度、覆盖范围），分 优 / 良 / 一般 / 差 四档。
多模型合成
GFS / ECMWF / 光追算法三路各自出分，再按 0.30 / 0.34 / 0.36 的权重合成，降低单一来源偏差。
弱 / 无霞色阶：白 → 黄 → 橙 → 红强霞

地图上那条从白到红的热力色阶，本教程也沿用为视觉线索——看到这条带子，就代表「霞光强度」。

FOR USERS · 上手指南

用户版：从一次查询到一张分享图

面向摄影爱好者与日常使用者。下面的顺序，基本就是一次完整使用的路径。

1 · 查一次朝霞 / 晚霞预报

  1. 选地点。在查询区搜索城市名，或允许浏览器定位，或点开「收藏机位」直接选常用点。地名走白名单，外源地名的异常字符会被安全处理。
  2. 选日期与时段。默认今天；时段在「朝霞 / 晚霞」之间切换（两者大气条件不同，分开算）。
  3. 读结论卡。核心三格：概率 %、质量评分、等级（优 / 良 / 一般 / 差）。下方还有「主要影响因素」逐项分解，告诉你这次是云量、湿度还是能见度在拖后腿。
  4. 看多模型。卡内列出 GFS / ECMWF / 光追三路各自的分数与合成结果；模型间分歧大时会在悬停信息里提示不确定性。
首屏只取单点结果（约 65 个加权调用）。地图数据必须由你显式点击才取，所以初次打开不会悄悄花掉你的额度。

2 · 看懂周边地图

地图把查询点周边 500 km 的霞光强度画成热力图，是「今天去哪个方向拍」最直观的答案。

白黄橙红 = 强霞

怎么把它画出来

  • 有缓存时自动画。上次看过的城市 + 日期，新开页会零请求直接画出来（走缓存快路径，不占额度）。
  • 没缓存时点击加载。点「加载周边地图」才会发起请求（约 171 个加权调用）。勾选框默认不勾选，因为它会直接影响你自己的日额度。

图上的几层信息

色面
采样点插值出的霞光强度，白→黄→橙→红分档。
等值线
档与档之间一条 1px 线（屏幕空间矢量，放大不变粗），帮你看清梯度。
数据范围虚线
采样点凸包外缘的虚线：线内是插值、线外是外推，外推区可信度更低。
经纬网
1° 网格底衬，可在图层开关里关闭。

五个图层开关

数值直标 / 采样点 / 可信度 / 经纬网 / 深色底图——按需开关，偏好会写进本地存储、重开页恢复。

交互

支持日期、时段、模型切换；鼠标悬停或点击地图出具体数值；外推区会附「离最近采样点多远」的距离口径。

可信范围别混用两个量：「在不在采样区里」（凸包）和「离最近采样点多远」是两个不同的概念。包内实测最远 85 km，贴着凸包顶点外侧只有 1.4 km 却已是外推。

3 · 趋势与最佳窗口

趋势曲线

未来若干天逐日打分曲线，可切换朝霞 / 晚霞。算好的结果会落盘缓存，重开页命中时零请求直接画出。

F3 · 最佳窗口日历

趋势的另一种读法：把未来 N 天按「哪天值得去」排成日历格（朝 / 晚两个色块 + 质量分），标出最值得去的前三名。点格子直接切过去——渲染这张日历零取数，只有点格子（你的显式意图）才走一次单点取数。

4 · 多观测点对比（F2）

回答「今天去哪儿拍」：收藏最多 5 个机位，一次取数横向按质量分排序。

  • 取数只能由「对比这些点」按钮触发；命中单点缓存的点不进请求（先单独查过的点零成本）。
  • 默认只比当前时段；界面会写明「本次将消耗约 N 个计费调用」。
  • 位置 / 日期 / 时段任一变化，对比结果作废（避免显示上一个地点的数字）。

5 · 分享与导出

一键分享卡 PNG

把结论卡导出为图片（纯 canvas 绘制，与页面同一套文案与配色），直接发到聊天工具。分享卡固定浅色底，发到任何环境都稳妥。

结果快照链接

链接带 snap= 参数，零气象请求即可还原结论（解码前限长并逐字段校验，恶意载荷只作纯文本落地）。语言、时段等随界面走。

6 · 偏好设置

单位制 / 12 小时制
温度单位、时间显示方式，按习惯切换。
语言
简体中文 / 繁體中文（中国台湾·香港用语）/ English，写进偏好与分享链接。优先级：URL > 偏好 > 浏览器语言 > 简体。
主题
浅色 / 深色 / 跟随系统三态。刷新不闪（引导脚本早于样式执行）。主题不进 URL——别人发的链接不该强制你的界面变黑。
9 个显示状态
数值直标 / 采样点 / 可信度 / 经纬网 / 深色底图 / 12 小时制 / 单位制 / 地图着色依据 / 算法模型，写进同一个本地键，重开页恢复。
刻意不持久化两类：位置与日期（由 URL 承载，避免与分享链接打架）；地图时段（由单点时段派生，存了会让「地图看晚霞、上方算朝霞」成为常态）。

7 · 本地校准（F4）

事后回来点一档「实际看到了什么」（6 档），本机累积后在结论卡下方多出一行本地校准：模型在这一档平均报多少、你标注了几次、实际出现率多少、偏差多少。

  • 只展示、不回改模型概率 / 等级 / 因素表任何一个字。
  • 只存本机——数据不出设备、可一键关闭、可清空。
  • 样本不够不给结论：累计 ≥8 次、且当前这一档 ≥3 次才显示，之前只显示进度。
  • 关掉 ≠ 删除：开关只关入口与展示，已存标注不删；清空是另一个按钮，且要二次确认。
  • 「没看到（无法判断）」不计入统计，以免系统性拉低校准。

8 · 移动端

  • 窄屏顶部信息条收成一行（不换行摊开），不挤占地图。
  • 地图提示卡改成贴底通栏并自带 × 关闭；可再点一次、点卡片外、或直接拖动地图收起。
  • 关闭后不留隐形热区（触摸交还地图）；拖动超过 12px 视为收卡、以下是点击。
  • 页面不可横向拖出空白；地图区单指可拖（手势交给地图 SDK）。

9 · 常见疑问

为什么地图有时直接显示、有时要点击？
有缓存（看过同城市同日期）开页自动画、零额度；无缓存仍需你点「加载周边地图」。
额度怎么算？
免费层按访客自己的出口 IP计（10000 次/天/人）。静态站不做代转，站点本身不消耗配额。
本地双击打开地图不显示？
预期行为：地图代理地址默认是占位符，双击打开时不起来，页面会说明原因；单点查询不受影响。要联调完整功能需本地预览构建。
深色的「深色底图」和主题切换是一回事吗？
不是。底图深色是地图数据图层开关；界面浅/深是主题。两者各管各的。

FOR DEVELOPERS · 工程说明

开发者版：结构、构建与部署

霞光预报的产物是 index.html——一个自包含 HTML（内联全部 JS 与城市/高程数据），可直接部署为静态站点；地图模块另有一个可选的同源服务端中转端点。

1 · 源码结构

单文件产物由脚本拼装，不要手改产物。

# 源（改这些）
tpl/template.html     版式来源（HTML + CSS + 3 个内联 <script> 占位块）
tpl/404.html          404 页模板（第二个产物，共用设计令牌）
_p2.js … _p6.js       业务代码片段
_pi18n.js             多语言词典（简/繁/英）
refs/*.txt            内联数据（城市表 / 地名别名 / 0.5° 高程网格 b64）

# 构建与产物
functions/            Cloudflare Pages Functions（地图代理，可选）
assemble.py           拼装 → index.html 与 404.html
mkpreview.py          拼装 → _check/preview.html（用 SDK 桩替换腾讯地图脚本）
_check/               回归套件
改动任何 _p*.js / tpl/ / refs/ 之后都必须重跑 assemble.py 与 mkpreview.py。两个产物都不许手改。

2 · 构建命令

# 默认构建（站点在域名根 /）
python assemble.py

# GitHub Pages 项目页（子路径 /sunglow/）
SITE_BASE=sunglow python assemble.py

# 带地图代理（同源路径，key 走环境变量，不进产物）
TMAP_SERVICE_HOST=https://你的域名/_TMapService python assemble.py

# 可选 PWA（多产 manifest/sw/图标，单文件约束默认仍成立）
PWA=1 SITE_BASE=sunglow python assemble.py

# 生成带 SDK 桩的预览文件（回归套件跑这个）
python mkpreview.py

不设 TMAP_SERVICE_HOST 时，assemble.py 回落到本地预览用的占位符形态，开发行为不变。

3 · 部署

3.1 纯静态（地图不可用）

把 index.html 丢到任意静态托管（Cloudflare Pages、GitHub Pages、对象存储）。查询、趋势、分享卡全部可用；地图模块因为没有腾讯地图 key 会显示一段说明。

免费层配额按访客自己的出口 IP计。静态站不做任何代转，站点本身不消耗配额。

3.2 带地图（Cloudflare Pages + Pages Functions）

腾讯地图 JS API 的 key 不能明文写进产物（单文件 HTML 谁都能看到 key 并刷配额）。已实现代理方案：

  1. 去 lbs.qq.com 申请 Web 端 (JS API) key，把站点域名加进白名单。
  2. 把本目录作为 Pages 项目（构建命令留空，产物目录 /）。functions/_TMapService/[[path]].js 会被自动识别为 Function。
  3. Pages 的 Settings → Environment variables 加 TMAP_KEY = 你的 key。
  4. 构建时把地图代理指到同源路径：TMAP_SERVICE_HOST=https://你的域名/_TMapService python assemble.py。

代理与前端同源 ⇒ 无 CORS、无混合内容。key 只存在于服务端环境变量，永不进入产物。

3.3 404 页

纯静态站没有前端路由，「访问不存在的路径」由托管平台兜底（Cloudflare Pages / GitHub Pages / Netlify 都取站点根下的 404.html 并以 404 返回）。assemble.py 一并生成，无需 rewrite 配置。页内地址写成站点根的绝对形式，由构建期注入 SITE_BASE。

3.4 可选 PWA

PWA=1 会多产 manifest.json / sw.js / icon-192.png / icon-512.png，可被「添加到主屏幕」且离线能打开。三条纪律：① SW 绝不缓存气象响应（只认预缓存名单）；② 缓存名带产物 sha256 前 12 位，内容一变旧缓存作废；③ 注册是「增强」——失败 / file:// 打开全部静默跳过。默认不开，因为它与「单文件产物」核心约束冲突。

3.5 本地预览

python assemble.py          # 生成 index.html
python mkpreview.py         # 生成 _check/preview.html（SDK 桩）

_check/preview.html 的地图 SDK 是桩实现（复刻 Heat 核函数叠加与投影），可离线、可断言、不消耗额度。回归套件全部跑这个文件。

5 · 已知边界（改动前必读）

额度
首屏只取单点（≈65）。地图必须由用户显式点击才取（≈171）。唯一例外是缓存命中自动画（零请求、零额度）。这条由 loadMapData 里「缓存快路径之后、网络调用之前」的一行 return false 保证。
可信范围
色面边界＝采样点凸包 + 70km 羽化；凸包之外即外推，叠可信度纱（覆盖已上色面积约 21.6%）。悬停卡另有「离最近采样点多远」的 90km 口径——与「在不在采样区」是两个量。
模型分歧
地图「模型分歧」只取三套模型极差；少于两套有值时返回「无数据」而非 0。
偏好持久化
9 个显示状态写进同一键（实测 112 字节）；应用顺序硬约束：必须在任何控件初值 / 派生状态赋值前调用。
趋势缓存
算好的 rows 落盘（≈1.9KB/条，上限 3 条），重开页命中零请求；不存原始响应（≈5MB 会撑爆配额）。权重/阈值一改用版本号兜住。
深色模式
三态；刷新不闪（引导脚本在 <style> 前）；color-scheme 跟着切；写进 DOM 的语义色要重画。分享卡固定浅色；主题不进 URL。
XSS
输出侧 esc() + 输入侧 safeLabel()（URL 地名白名单）。新增 render 代码必须走这两个函数。仍未做：CSP 与其余 44 处分批替换。
F2 / F3 / F4
F3 日历渲染零取数，点格子才取数；F2 取数只能由按钮触发、命中缓存不进请求、上限 5 点；F4 只展示不回改、样本不够不给结论、关掉≠删除。
手机端布局
任何横向滚动容器必须 min-width:0；#map 必须 touch-action:none 且不能设在 .mapwrap；判越界用 documentElement.clientWidth 而非 innerWidth。

6 · 合规

在中国境内展示地图，底图服务需具备测绘资质。腾讯地图是合规的；为省一个 key 换成 OSM 等境外底图会把合规问题一起换进来，不建议。数据源：气象 / 空气质量来自 Open-Meteo（免费公开、非商业），省界来自阿里云 DataV，地图来自腾讯位置服务——请遵守各自服务条款。

2 · 最值得拍的 5 个亮点

结论卡

概率 + 质量评分，数字衬线大字

结论卡用大号衬线数字呈现概率 % 与质量分，配优/良/一般/差等级与「主要影响因素」分解——截图即干货，观众一眼看懂。

周边 500 km 霞光分布

热力图把「去哪个方向拍」画出来。白→黄→橙→红色阶 + 等值线 + 数据范围虚线，演示时直接说「红色那片就是今晚最该去的地方」。

F3 日历

最佳窗口：哪天去直接排好

未来 N 天按「哪天值得去」排成日历格，标出前三名。适合做「未来一周什么时候拍照最好」这类选题。

F2 对比

多机位对比：今天去哪儿拍

收藏最多 5 个机位一次取数横向排序。演示「家附近 vs 海边 vs 山顶，今晚哪个出片」最直观。

分享

一键分享卡 / 快照链接

结论卡导出 PNG 直接发群；snap= 链接零请求还原结论，别人点开就是同一张预报。降低观众「我也想试试」的门槛。

本地校准

越用越懂你那片天

事后回填「实际看到了什么」，本机累积出本地校准。强调「纯展示不回改模型、数据不出设备」——隐私友好，适合做信任感叙事。

3 · 适合的题材

4 · 演示叙事线（录屏脚本）

  1. 抛出痛点：「每次等晚霞都靠赌，今天教你用数据赌。」
  2. 一次查询：搜城市 → 切晚霞 → 结论卡大数字 + 因素分解。
  3. 放大地图：点「加载周边地图」→ 指红色区域说「去这儿」。
  4. 拉长时间：开 F3 日历 → 「这周三是冠军」。
  5. 横向比较：开 F2 对比 → 「山顶比海边稳」。
  6. 收尾转化：导出分享卡 / 发快照链接 → 「链接放评论区，自己查你那片天」。
移动端演示：窄屏顶部收成一行、提示卡贴底通栏、拖动地图收卡——这些交互本身就很「产品感」，适合慢动作展示。

5 · 可放心引用的卖点

  • 免费、无需注册，纯前端直连公开气象接口（Open-Meteo）。
  • 三模型合成（GFS / ECMWF / 光追，权重 0.30 / 0.34 / 0.36），降低单一来源偏差。
  • 隐私友好：本地校准数据只存本机、可关闭可清空、不回改模型。
  • 额度对访客友好：首屏只取单点，地图显式点击才取，缓存命中零请求。
  • 可装成 App（PWA，可选），离线也能打开。

6 · 注意事项（别踩坑）

额度
免费层按访客自己的出口 IP 计（10000 次/天/人）。做演示时自己多刷几次没关系，但别误导观众「无限调用」。
地图需部署
双击本地文件打开时地图不显示（占位符形态），这是预期行为；完整地图功能需要带代理的部署。
合规底图
中国境内展示用地图需测绘资质，项目用的腾讯地图是合规方案；不要为省事换成境外底图。
概率是「霞光」不是「出太阳」
避免观众误解——它预报的是低空霞光出现的可能性与质量，不是晴雨。
