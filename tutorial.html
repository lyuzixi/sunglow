演示素材

它到底在算什么

一句话：把「今晚有没有火烧云」从玄学变成可量化的概率与质量分。

朝霞 / 晚霞
日出前与日落后的低空霞光（火烧云）。两者的大气条件不同，所以应用分开预报、可分别切换。
概率 %
出现霞光的可能性，由云量、湿度、能见度等条件推算 —— 不是「会不会出太阳」。
质量评分
在「会出现」的前提下，霞光的观赏质量（色彩浓度、覆盖范围），分优 / 良 / 一般 / 差四档。
多模型合成
GFS / ECMWF / 光追算法三路各自出分，再按 0.30 / 0.34 / 0.36 的权重合成，降低单一来源偏差。
弱 / 无霞色阶：白 → 黄 → 橙 → 红强霞

地图上那条从白到红的热力色阶，本教程沿用为视觉线索：看到这条带子，就代表「霞光强度」。

1 · 查一次朝霞 / 晚霞预报

  1. 选地点。在查询区搜索城市名，或允许浏览器定位，或点开预设里的常用地点。地名走白名单，外源地名的异常字符会被安全处理。
  2. 选日期与时段。默认今天；时段在「朝霞 / 晚霞」之间切换 —— 两者大气条件不同，分开算。
  3. 读结论卡。核心三格：概率 %、质量评分、等级（优 / 良 / 一般 / 差）。下方「主要影响因素」逐项分解，告诉你这次是云量、湿度还是能见度在拖后腿。
  4. 看多模型。卡内列出 GFS / ECMWF / 光追三路各自的分数与合成结果；模型之间分歧大时，悬停信息里会提示不确定性。
首屏只取单点结果（约 65 个加权调用）。地图数据必须由你显式点击才取，所以初次打开不会悄悄花掉你的额度。

2 · 看懂周边地图

地图把查询点周边 500 km 的霞光强度画成热力图，是「今天去哪个方向拍」最直观的答案。

怎么把它画出来

  • 有缓存时自动画。上次看过的城市 + 日期，新开页会零请求直接画出来（走缓存快路径，不占额度）。
  • 没缓存时点击加载。点地图面板里的「刷新地图」才发起请求（约 171 个加权调用）—— 它直接影响你自己的日额度。

图上是什么

色面
采样点插值出的霞光强度，白 → 黄 → 橙 → 红分档。色阶是固定的 0–100 绝对刻度，所以同一片区域的深浅可以跨日期直接对比。
云纹
采样点上的云量，按四档画成斜纹。晴天不画（否则整张图都是纹路，等于没有信息），有云才显形。
等值线
档与档之间一条 1px 线（屏幕空间矢量，放大不变粗），帮你看清梯度往哪边走。
数据范围虚线
采样点凸包外缘的虚线：线内是插值、线外是外推，外推区可信度更低。
经纬网
1° 网格底衬，可在显示层里关闭。

四个显示层开关

数值直标 / 采样点 / 云纹 / 经纬网 —— 按需开关，偏好写进本地存储，重开页恢复。

交互

地图面板里可切时段、日期、模型与着色依据；鼠标悬停或点击出具体数值，外推区会附「离最近采样点多远」的距离口径；右下角可全屏。

可信范围别混用两个量：「在不在采样区里」（凸包）和「离最近采样点多远」是两个不同的概念。包内实测最远 85 km，贴着凸包顶点外侧只有 1.4 km 却已经是外推。

3 · 趋势与最佳窗口

趋势曲线

未来十天逐日打分，可切换朝霞 / 晚霞。算好的结果会落盘缓存，重开页命中时零请求直接画出。

最佳窗口日历

趋势的另一种读法：把未来几天按「哪天值得去」排成日历格（朝 / 晚两个色块 + 质量分），并标出前三名。点格子直接切过去 —— 渲染这张日历零取数，只有点格子（你的显式意图）才走一次单点取数。

4 · 多观测点对比

回答「今天去哪儿拍」：收藏最多 5 个机位，一次取数横向按质量分排序。

  • 取数只能由「对比这些点」按钮触发；命中单点缓存的点不进请求（先单独查过的点零成本）。
  • 默认只比当前时段；界面会写明「本次将消耗约 N 个计费调用」。
  • 位置 / 日期 / 时段任一变化，对比结果作废 —— 避免显示上一个地点的数字。

7 · 本地校准

事后回来点一档「实际看到了什么」，本机累积之后，结论卡下方会多出一行本地校准：模型在这一档平均报多少、你标注了几次、实际出现率多少、偏差多少。

  • 只展示、不回改模型概率 / 等级 / 因素表任何一个字。
  • 只存本机 —— 数据不出设备、可一键关闭、可清空。
  • 样本不够不给结论：累计 ≥8 次、且当前这一档 ≥3 次才显示，之前只显示进度。
  • 关掉 ≠ 删除：开关只关入口与展示，已存标注不删；清空是另一个按钮，且要二次确认。
  • 「没看到（无法判断）」不计入统计，以免系统性拉低校准。

8 · 手机端

  • 顶部两行：第一行是目录、标题、语言与主题按钮，第二行是当前结果徽标。滚到哪都能开目录。
  • 地图提示卡改成贴底通栏并自带关闭；可再点一次、点卡片外，或直接拖动地图收起。
  • 关闭后不留隐形热区（触摸交还地图）；拖动超过 12px 视为收卡，以下算点击。
  • 页面不能横向拖出空白；地图区单指可拖，手势交给地图 SDK。

9 · 常见疑问

为什么地图有时直接显示、有时要点击？
有缓存（看过同城市同日期）开页自动画、零额度；无缓存仍需你点「刷新地图」。
额度怎么算？
免费层按访客自己的出口 IP 计（10000 次 / 天 / 人）。静态站不做代转，站点本身不消耗配额。
本地双击打开地图不显示？
预期行为：地图代理地址在没有部署时是一个占位符，页面会说明原因；单点查询不受影响。要联调完整功能需按开发者版的说明构建一次。
地图的深浅和界面主题是一回事吗？
现在是一回事：底图深浅跟随界面主题（浅色主题配浅底图，深色配深底图）。原先那个独立的「深色底图」开关已取消 —— 一个页面不该有两套深浅。

2 · 构建命令

# 默认构建（站点在域名根 /）
python assemble.py

# GitHub Pages 项目页（子路径 /sunglow/）
SITE_BASE=sunglow python assemble.py

# 带地图代理（同源路径，key 走环境变量，不进产物）
TMAP_SERVICE_HOST=https://你的域名/_TMapService python assemble.py

# 可选 PWA（多产 manifest / sw / 图标，单文件约束默认仍成立）

# 生成带 SDK 桩的预览文件（回归套件跑这个）
python mkpreview.py

不设 TMAP_SERVICE_HOST 时，assemble.py 回落到本地预览用的占位符形态，开发行为不变。

3 · 部署

3.1 纯静态（地图不可用）

把 index.html（以及可选的 tutorial.html、404.html）丢到任意静态托管：Cloudflare Pages、GitHub Pages、对象存储。查询、趋势、分享卡全部可用；地图模块因为没有腾讯地图 key 会显示一段说明。

免费层配额按访客自己的出口 IP 计。静态站不做任何代转，站点本身不消耗配额。

3.2 带地图（Cloudflare Pages + Pages Functions）

腾讯地图 JS API 的 key 不能明文写进产物（单文件 HTML 谁都能看到，拿去刷配额）。已实现代理方案：

  1. 去 lbs.qq.com 申请 Web 端（JS API）key，把站点域名加进白名单。
  2. 把本目录作为 Pages 项目（构建命令留空，产物目录 /）。functions/_TMapService/[[path]].js 会被自动识别为 Function。
  3. Pages 的 Settings → Environment variables 加 TMAP_KEY = 你的 key。
  4. 构建时把地图代理指到同源路径：TMAP_SERVICE_HOST=https://你的域名/_TMapService python assemble.py。

代理与前端同源 ⇒ 无 CORS、无混合内容。key 只存在于服务端环境变量，永不进入产物。

3.3 404 页

纯静态站没有前端路由，「访问不存在的路径」由托管平台兜底（Cloudflare Pages / GitHub Pages / Netlify 都取站点根下的 404.html 并以 404 返回）。assemble.py 一并生成，无需 rewrite 配置；页内地址写成站点根的绝对形式，由构建期注入 SITE_BASE。

3.4 可选 PWA

PWA=1 会多产 manifest.json / sw.js / 两枚图标，可被「添加到主屏幕」且离线能打开。三条纪律：① SW 绝不缓存气象响应（只认预缓存名单）；② 缓存名带产物 sha256 前 12 位，内容一变旧缓存作废；③ 注册是「增强」—— 失败或 file:// 打开全部静默跳过。默认不开，因为它与「单文件产物」的核心约束冲突。

5 · 已知边界（改动前必读）

额度
首屏只取单点（约 65）。地图必须由用户显式点击才取（约 171）。唯一例外是缓存命中自动画（零请求、零额度）—— 由「缓存快路径之后、网络调用之前」的一行提前返回保证。
色面与范围
色面值域是固定的 0–100 绝对刻度（不做当日拉伸），边缘取采样点凸包并仅向外羽化；凸包之外即外推，用虚线标出。悬停卡另有「离最近采样点多远」的口径 —— 与「在不在采样区」是两个量。
云纹
按云量分四档画斜纹，晴档不画（否则整张图都变闷）。档界同时是图例边界；图例里「晴」是空心描边，代表「这里没有纹路是因为没有云」。
模型分歧
地图的「模型分歧」只取三套模型的极差；少于两套有值时返回「无数据」而不是 0。
偏好持久化
所有显示类偏好写进同一个本地键；应用顺序有硬约束 —— 必须在任何控件初值 / 派生状态赋值之前调用。
趋势缓存
算好的 rows 落盘（约 1.9KB / 条，上限 3 条），重开页命中零请求；不存原始响应（约 5MB，会撑爆配额）。权重 / 阈值一改就用版本号兜住。
深色模式
三态；刷新不闪（引导脚本在 <style> 之前）；color-scheme 跟着切；写进 DOM 的语义色要重画。分享卡固定浅色；主题不进链接。">三态；刷新不闪（引导脚本在 <style> 之前）；color-scheme 跟着切；写进 DOM 的语义色要重画。分享卡固定浅色；主题不进链接。
XSS
输出侧 esc() + 输入侧 safeLabel()（URL 地名白名单）。新增渲染代码必须走这两个函数；仍未做：CSP 与其余分批替换。
F2 / F3 / F4
F3 日历渲染零取数，点格子才取数；F2 取数只能由按钮触发、命中缓存不进请求、上限 5 点；F4 只展示不回改、样本不够不给结论、关掉≠删除。
手机端布局
任何横向滚动容器必须 min-width:0；#map 必须 touch-action:none 且不能设在 .mapwrap；判越界用 documentElement.clientWidth 而不是 innerWidth。

6 · 合规

在中国境内展示地图，底图服务需具备测绘资质。腾讯地图是合规的；为省一个 key 换成 OSM 等境外底图，会把合规问题一起换进来，不建议。

1 · 一句话开场

「它是一个把『今晚有没有火烧云』从玄学变成概率和评分的工具 —— 而且免费、不用注册、纯网页。」

这句同时覆盖了差异化（量化而非玄学）与易得性（免费 / 无注册 / 纯前端），适合做短视频开头或图文首段。

2 · 最值得讲的五个亮点

结论卡

概率 + 质量评分，衬线大字

结论卡用大号衬线数字呈现概率 % 与质量分，配优 / 良 / 一般 / 差等级与「主要影响因素」分解 —— 截图即干货，观众一眼看懂。

地图

周边 500 km 霞光分布

热力图把「去哪个方向拍」画出来。白 → 黄 → 橙 → 红色阶 + 等值线 + 数据范围虚线，演示时直接说「红色那片就是今晚最该去的地方」。

最佳窗口

哪天去，日历直接排好

未来几天按「哪天值得去」排成日历格并标出前三名。适合做「未来一周什么时候拍照最好」这类选题。

多机位对比

今天去哪儿拍

收藏最多 5 个机位，一次取数横向排序。演示「家附近 vs 海边 vs 山顶，今晚哪个出片」最直观。

分享

分享卡与快照链接

结论卡导出 PNG 直接发群；snap= 链接零请求还原结论，别人点开就是同一张预报。降低观众「我也想试试」的门槛。

本地校准

越用越懂你那片天

事后回填「实际看到了什么」，本机累积出本地校准。强调「纯展示不回改模型、数据不出设备」—— 隐私友好，适合做信任感叙事。

3 · 适合的题材

题材切入点
摄影教程用最佳窗口日历选拍摄日、用多机位对比选机位、用地图定方向。
天气 / 大气科普朝霞晚霞大气条件不同、为什么分两个时段、模型分歧代表什么。
出行 / 生活攻略「今晚值不值得专门跑出去拍」「未来一周哪天最适合」。
工具推荐免费、无注册、纯前端、隐私友好、可装成 App（PWA）。

4 · 演示叙事线

  1. 抛出痛点：「每次等晚霞都靠赌，今天教你用数据赌。」
  2. 一次查询：搜城市 → 切晚霞 → 结论卡大数字 + 因素分解。
  3. 放大地图：点「刷新地图」→ 指红色区域说「去这儿」。
  4. 拉长时间：开最佳窗口日历 → 「这周三是冠军」。
  5. 横向比较：开多机位对比 → 「山顶比海边稳」。
  6. 收尾转化：导出分享卡 / 发快照链接 → 「链接放评论区，自己查你那片天」。
移动端演示：顶部两行、提示卡贴底通栏、拖动地图收卡 —— 这些交互本身就很「产品感」，适合慢动作展示。

5 · 可放心引用的卖点

  • 免费、无需注册，纯前端直连公开气象接口（Open-Meteo）。
  • 三模型合成（GFS / ECMWF / 光追，权重 0.30 / 0.34 / 0.36），降低单一来源偏差。
  • 隐私友好：本地校准只存本机、可关闭可清空、不回改模型。
  • 额度对访客友好：首屏只取单点，地图显式点击才取，缓存命中零请求。
  • 可装成 App（PWA，可选），离线也能打开。

6 · 注意事项（别踩坑）

额度
免费层按访客自己的出口 IP 计（10000 次 / 天 / 人）。演示时自己多刷几次没关系，但别让观众以为「无限调用」。
地图需要部署
双击本地文件打开时地图不显示（代理是占位符形态），这是预期行为；完整地图功能需要带代理的部署。
合规底图
中国境内展示地图需测绘资质，项目用的腾讯地图是合规方案；不要为省事换成境外底图。
概率指的是霞光
避免观众误解 —— 它预报的是低空霞光出现的可能性与质量，不是晴雨。
