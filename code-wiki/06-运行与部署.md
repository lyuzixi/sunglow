# 06 · 运行与部署

## 1. 本地开发流程

```bash
# 1. 改源码：tpl/ · _pi18n.js · _p2.js…_p6.js · refs/
# 2. 重新拼装产物 + 预览页（必须成对跑）
python assemble.py            # → index.html / 404.html
python mkpreview.py           # → _check/preview.html（腾讯地图 SDK 换成桩）

# 3. 联调
#   · 页面功能：直接开 index.html（地图除外，见下）
#   · 地图模块：开 _check/preview.html（桩 SDK，离线可断言、零额度）

# 4. 回归
python _check/all.py          # 26 项总表
```

**铁律**：改动任何 `_p*.js` / `tpl/` / `refs/` 之后都必须重跑 `assemble.py && mkpreview.py`。
两个产物（`index.html`、`404.html`）**都不许手改**；忘了重建 preview 会让整套断言测旧代码。

### 1.1 双击打开 index.html 的预期行为

地图代理地址默认是占位符形态，`file://` 下地图不会起来、页面会显示原因说明——**这是预期行为**，
单点查询/趋势/分享卡不受影响。完整地图能力需要部署代理或用 preview 桩页。

## 2. 构建环境变量

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `TMAP_SERVICE_HOST` | 回落本地预览占位符形态 | 地图代理端点；部署时设 `https://你的域名/_TMapService` |
| `SITE_BASE` | `/` | 站点根绝对路径（自动补首尾 `/`）；GitHub Pages 项目页设 `sunglow` |
| `PWA` | 关 | `1` 时多产 `manifest.json` / `sw.js` / 图标 |
| `OUT_DIR` | 仓库根 | 输出目录（供探针产出"另一套构建"而不覆盖交付产物） |

```bash
# 子路径部署（GitHub Pages 项目页）
SITE_BASE=sunglow python assemble.py

# 带地图的 Cloudflare Pages 部署
TMAP_SERVICE_HOST=https://你的域名/_TMapService python assemble.py

# PWA 版
PWA=1 SITE_BASE=sunglow python assemble.py
```

## 3. 三种部署形态

### 3.1 纯静态（地图不可用）

把 `index.html`（+ `404.html`）丢到任意静态托管（Cloudflare Pages / GitHub Pages / 对象存储）。
查询、趋势、分享卡全部可用；地图显示一段说明。**站点本身不消耗任何额度**
（免费层配额按访客自己的出口 IP 计）。

### 3.2 带地图（Cloudflare Pages + Pages Functions）

1. 在 [lbs.qq.com](https://lbs.qq.com) 申请 **Web 端 (JS API)** key，把站点域名加进白名单；
2. 把本目录作为 Pages 项目（构建命令留空，产物目录 `/`）；
   `functions/_TMapService/[[path]].js` 自动识别为 Function；
3. Pages → Settings → Environment variables 加 `TMAP_KEY = 你的 key`；
4. 构建时指回同源代理：`TMAP_SERVICE_HOST=https://你的域名/_TMapService python assemble.py`。

key 只存在服务端环境变量，**永不进入产物**；代理与前端同源 ⇒ 无 CORS、无混合内容。

### 3.3 GitHub Pages 项目页（子路径）

本仓库 Pages 开在 `https://lyuzixi.github.io/sunglow/`（**子路径**），
推 GitHub 前按子路径构建：`SITE_BASE=sunglow python assemble.py`（404 页写 `/sunglow/`）。

> 为什么 404 页不能用相对地址：`404.html` 在**请求的那个 URL** 下被返回，
> 相对地址按 `/a/b` 解析成 `/a/index.html`，越深错得越离谱 —— 所以走"构建期注入站点根"这条路。

### 3.4 404 页机制

纯静态站没有前端路由，"未知路径"由托管平台兜底：匹配不到文件时取站点根 `404.html` 并返回 404
（Cloudflare Pages / GitHub Pages / Netlify 同一约定），**不需要任何 rewrite 配置**。
页内"返回首页"是真链接（无 JS 也可用），"返回上一页"仅在确认有上一页时显形。

### 3.5 PWA（可选，默认关闭）

`PWA=1` 产出 manifest / sw / 图标，页面可"添加到主屏幕"且离线可开。三条纪律：

1. SW **绝不缓存气象响应**（过期预报比没有预报更危险），只预缓存同源静态壳 + 404 页；
2. 缓存名带产物内容 **sha256 前 12 位**，内容一变旧缓存自动作废；
3. 注册是"增强"—— 没有 SW / 注册失败 / `file://` 打开一律静默跳过；
   注册脚本**不新增内联 `<script>` 块**（块数 4 是不变量），脚本地址从 `link[rel=manifest]` href 推导。

> 默认不开的原因：单文件产物与 SW 注册（须同源 http(s) 真实 URL）物理冲突，
> 取舍是"默认仍是 1 个文件，想要可安装的人自己开 `PWA=1`"。

## 6. 常见问题

| 现象 | 原因 / 处置 |
| --- | --- |
| 改了 JS 但页面/探针没变化 | 忘了重建产物与 preview；重跑 `assemble.py && mkpreview.py` |
| 本地打开地图不工作 | `file://` + 占位代理地址，属预期；用 preview 或部署代理 |
| 地图显示"部署没配"说明 | `TMAP_SERVICE_HOST` 未设或仍是占位符形态 |
| 404 页"返回首页"跳错 | `SITE_BASE` 与实际部署路径不符（子路径要设 `sunglow`） |
| 构建报"占位符出现 N 次" | 数据占位符必须恰出现 1 次，检查 `tpl/` 与 `refs/` 是否被手改 |
| 探针 EADDRINUSE | 探针各占固定调试端口，不可并行跑（设计如此） |
